# Cloudflare 在线文件管理器

基于 **Cloudflare Workers + R2 + KV** 的极简在线网盘：可以**建文件夹、新建文本、上传文件**，并支持只读分享链接。
无需服务器、无需数据库，文件本体存在 R2，分享口令存在 KV。

打开文件时**按类型自动选择怎么显示**：Markdown 渲染成网页、JSON 折叠成树、CSV 变成表格、
代码高亮、图片/音视频/PDF 直接预览 —— 认不出的格式自动退回纯文本，**不会出现打不开的文件**。

## 🚀 功能概览

界面是「左侧文件管理 + 右侧编辑/列表」的布局，接近常见的在线笔记工具，上手即用。

- **左侧文件管理栏**：顶部搜索框（**管理端是全文搜索**：文件名 + 正文内容，见下节；**分享页只搜文件名和目录名**），下面是一棵**能看清全部内容的目录树**（见下节），点一下直接在右侧打开
- **侧栏宽度随便拖**：左栏和右栏之间有一条可拖拽的分隔条，左右拖动即可改宽度；
  **双击分隔条（或点「目录」右侧的双向箭头）会按最长的文件名自动撑到刚好装下**，全名不再被省略号截断
- **列表排序**：按 **名称 / 类型 / 大小 / 修改时间** 排序，点表头或工具栏下拉都行，再点一次切换升降序，偏好会记住
- **打包下载**：文件夹也能整个下成 zip，勾选多个文件/文件夹可以一次打包（浏览器端生成，不限服务端 CPU，见「📦 打包下载」）
- **文件类型列**：除了名字旁边的后缀徽标，还有独立的「类型」列（文档 / 代码 / 配置 / 数据表 / 图片 / 视频 / 音频 / PDF / 压缩包 / 文件夹 / 无扩展名）
- **框选多选**（桌面）：在列表里**按住鼠标拖出一个选框**，框到的文件/文件夹批量勾选；按住 `Ctrl`/`Shift` 拖是追加选择；
  `Shift + 点击` 勾选框还能从上次点到这次之间整段连选
- **长按多选**（手机 / 平板）：**长按任意一行约 0.4 秒**进入多选模式，之后点哪行就勾哪行（见下节）
- **PWA：可以装到手机桌面**：全站支持"添加到主屏幕"——**全屏独立运行、无浏览器地址栏**，
  图标与主题色自动生成（不依赖任何图片文件）。Android 走"安装应用"，iOS 走"添加到主屏幕"（见下节）
- **文件后缀徽标**：列表、目录树、搜索结果里，文件名旁边都挂一个小徽标（`MD` / `PY` / `JSON` / `PNG` …）并按类别着色。
  目录树里长文件名会被省略号截断，**但徽标始终看得见**
- **统一渲染层**：打开文件时按扩展名分派到对应渲染器（见下节）—— Markdown / JSON / CSV / 代码高亮 / SVG·HTML / 图片音视频 PDF，认不出的自动退回纯文本
- **编码自动识别**：UTF-8 / GBK / GB18030 / Big5 / UTF-16 都能正确解码，**老式 GBK 中文 txt 不会再乱码**；保存时统一转成 UTF-8
- **编辑器视图**：大号编辑区 + 行号槽 + 顶部工具栏（**发布**、字号调节、自动换行、查找替换、**复制全文**、源码/预览、**当前文件完整路径**、以及文件操作：下载/分享/重命名/移动/删除/返回列表），右下角实时统计（行数 / 字符 / 单词 / 选中）
- **编辑自动保存，改动不会丢**：**停手 5 秒就静默存到服务器**，另外失焦、切到后台、关页面时各兜一次 ——
  不存在"改了忘保存就关网页，内容丢了"这种事（`Ctrl+S` 仍可立即保存）。详见「编辑与分享分离」一节
- **没真的改就不存**：改完又改回来、`Ctrl+Z` 撤销回原样 —— **一个请求都不发**。
  纯前端逐字比对，不消耗任何配额。详见「省资源：三道坎」一节
- **搜索索引同步建，改完立刻能搜到**：保存文件时**当场**把这个文件写进搜索索引 ——
  所以改完文件**第一次搜索**就能搜到新内容，不会出现"要再搜一次才找得到"的情况。
- **编辑与分享分离（发布机制）**：自动保存只写**草稿**，**只有点「发布」才会更新分享页**。
  改到一半、对内容还不满意、或者里面有不想给访客看的草稿 —— 分享页纹丝不动；确认好了再点一次发布。
  **没有分享链接的文件，「发布」是灰的**（并提示去点「分享」）—— 没有任何链接指向它时，发布只是往
  影子树里拷一份没人会读的内容；文件**在某个已分享的目录里**时照样可点，因为它确实会出现在分享页上。详见「编辑与分享分离」一节
- **🔒 受保护文件夹（防误删）**：把重要目录标成「受保护」后，**里面的文件/子文件夹在删除时强制校验管理员密码**，
  **取消保护本身也要密码**（防手滑解锁），**跨越保护区边界的移动也要密码**（搬出、搬入都验，含批量移动），
  防止手滑或批量操作把要紧的东西清掉或挪丢。受保护的文件夹**永远排在列表最前面**，
  并单独占一个「🔒 受保护文件夹」分区色带（配金色专属文件夹图标 + 红色 **🔒 受保护** 徽标 + 左侧金色色条），
  目录树里是两个各自带边框的独立板块 + 小锁，一眼可辨；
  新建文件夹时可勾选，已有文件夹可在 **⋯ → 设为受保护文件夹 🔒** 里随时上锁。详见「🔒 受保护文件夹」一节
- **打开不抢焦点**：不论 PC 还是手机，打开网页、打开文件都**不会自动把光标放进文本框** ——
  手机上一聚焦就会弹出软键盘、把半个页面顶掉，非常影响"先看两眼"的场景；想编辑点一下正文即可
- **文本区自动铺满**：编辑器里的文本区会**撑满整个可用高度** —— 打开一个只有两行的文件，
  也不会在文本框下方空出一大片（靠一条从 body 到 #edt 的 flex 链，见「高度链」一节）
- **一键复制全文**：编辑器工具栏上的「复制全文」直接在文本框上方，点一下复制当前全部内容（不用全选、不用键盘）
- **分享就在手边**：编辑器工具栏的「分享」点开就是分享弹窗 —— 和列表行上的「分享」完全一致，填口令/选有效期/点生成。
  编辑器下方原来那个"分享设置"内嵌面板**已删除**：同一个功能摆两处，用户在上面点了以为没反应、还得自己往下找，反而困惑
- **查找替换**：`Ctrl+F` / `Ctrl+H` 打开查找条，支持**全部命中高亮**、上一个/下一个、**正则表达式**、区分大小写、替换与全部替换
- **编辑快捷键**：`Ctrl+S` 立即保存、`Tab`/`Shift+Tab` 缩进、`Alt+↑↓` 移动整行、`Ctrl+/` 注释切换、成对符号自动闭合与选中包裹
- **Markdown 大纲**：编辑 `.md` 时右侧浮出标题大纲，点一下跳到对应行；`F3` 在命中之间跳转
- **本地草稿保险**：编辑中每 2.5 秒把内容存到浏览器本地，误关闭/崩溃后重新打开会提示恢复
  （这是自动保存之外的第二层保险：自动保存解决"忘了保存"，本地草稿解决"根本没写完/网络断了"）
- **大文件自动降级**：内容超过 512KB 时自动关掉行号与高亮，优先保证输入不卡
- **自动换行**：**默认开启**，工具栏上一键切换（或按 `Alt+Z`），设置会记住；只读查看器同样支持
- **一键刷新页面**：顶栏操作区有一个刷新按钮（**排在退出按钮左侧**；只读分享页上则是唯一按钮），点一下重载当前页面
- **正文里的网址可点击（仅编辑器）**：编辑区里完整的网址（`http(s)://…` 或裸 `www.…`）**保持纯文本长相**
  （不改字色、不加底纹，和正文一模一样），只在**网址末尾挂一个极小的浅蓝链接图标**（11px、只有图标没有文字），
  点图标就在新标签打开；网址结尾的标点（中英文都算）不会被吃进链接，`javascript:` 之类的伪协议永远不会被做成链接。
  正文超过 256KB 时不再渲染图标，优先保证输入流畅
- **只读分享页不挂图标**：分享页正文保持原样纯文本，不做任何前端加工 —— 面向访客与下游程序，越"干净"越稳
- **打开网址的两条路**（都不打扰编辑）：桌面上 **`Ctrl`/`Cmd` + 点击**正文里的网址直接打开；
  任何设备上都可以点网址末尾那个**小图标**。普通点击**永远只是放光标**，不会误跳走，也不抢长按复制
- **分享设置**：唯一入口就是「分享」弹窗（编辑器工具栏、列表行 ⋯ 菜单、目录树右键三处都能打开）。
  输入自定义 Token、选有效期、一键生成，链接**带 `.yaml` / `.txt` 等后缀**，并附**二维码**方便手机扫码
- **分享状态即时更新**：生成或取消分享后，列表的「已分享」徽标和分享管理**立刻**同步，不用刷新页面。
  （Cloudflare KV 是最终一致的，写后立刻读可能拿到旧数据；所以本会话的增删用乐观合并叠加在缓存上，KV 追上来后自动让位）
- **从分享管理一键定位**：每个分享分组路径旁有 **◎ 定位**按钮，点击直接跳到该文件所在的目录并**打开它（可编辑）**——
  在分享管理里发现"这个文件该改改了"，不用自己去翻目录找
- **行内操作收进 ⋯ 菜单**：列表每行只剩一个 ⋯ 按钮（悬停该行或选中时出现，触屏常显），
  点开是完整操作菜单 —— 打开 / 预览 / 下载 / 分享 / 重命名 / 移动 / 删除；**打开文件直接点文件名**，不必进菜单
- **文件夹管理**：新建文件夹，多级目录；顶部面包屑每一级都可点。
  **编辑器里也有一条完整路径条**（如 `根目录 / 笔记 / 说明.md`），目录级可点，手机上一眼知道文件在哪、一键跳到任一级
- **返回键 = 回上一级目录**：切换目录会写进浏览器历史，所以手机/浏览器的返回键是**退到上一级目录**，
  而不是直接离开整个网站（以前用 `replaceState`，历史里永远只有一条，一按返回就退出）
- **新建文本**：网页里直接写文件，可反复编辑保存
- **上传文件**：工具栏按钮多选上传，或直接把文件**拖进页面**，带进度条
- **上传文件夹**：`上传文件夹`按钮选择整个目录，或把文件夹**直接拖进页面** —— 保留原有目录结构，
  空文件夹也会保留；上传前弹窗告知「N 个文件 / M 个文件夹 / 合计体积」
- **同名文件处理**：上传前先比对云端，弹窗里可以选择 **跳过 / 覆盖 / 都保留（自动加序号）**，
  并给出「完全一致」与「可能不同」的分组统计（详见下文）
- **重命名**：列表每行有「重命名」按钮，目录树里悬停出现 `⋯`（也可**右键**），**回车即改**，扩展名默认不选中
- **移动**：独立的移动弹窗，浏览目标目录后再确定（也能顺便改名）
- **批量操作**：每行左侧勾选（或点「全选本页」），底部浮出操作条 —— **批量移动 / 批量删除**
  - 删文件夹会**递归删掉里面全部内容**，删之前弹窗会说明有几文件夹几文件、且不可撤销
  - 批量移动会列出目标目录供浏览选择；**选中的文件夹自身会被置灰**（不能移进它自己内部）
- **单文件分享（直连）**：给单个文件生成链接，打开就是正文，**没有页面外壳**（HTML 例外，见「HTML 单文档分享」一节）
- **目录分享（只读）**：给对方一个只读浏览页，可进子目录、**渲染预览**（Markdown/表格/代码）与下载
- **图片 / 音视频 / PDF 预览**：列表里点「预览」开灯箱，支持缩放、旋转、切换；分享页访客同样可用
- **分享状态一眼可见**：列表、目录树、编辑器标题上都会标出「🔗 已分享」，
  工具栏的 **「分享管理」** 面板列出全部链接（按目标分组，可复制 / 打开 / 取消）
- **目录树一点直达分享链接**：目录树里已分享条目后面的 🔗 图标可以直接点——
  只有 1 条链接就**新标签页直接打开**，多条就弹分享面板任选一条。右键点它还是操作菜单，不会误触
- **每条分享都能单独发布 / 撤回**：分享面板和分享管理里，每行都有 **「发布」** 和 **「撤回」** 两个按钮，
  并用 **🟢 已发布 / 🟡 待发布** 标签标出当前状态。「撤回」只让分享页暂时看不见，**草稿和链接都留着**，随时能发回来
- **分享管理可一键补发**：从旧版本升级上来时，历史分享在影子树里还没有副本，链接会打不开。
  面板里会统计「有 N 条还没发布」，点 **「全部发布」** 一次性补齐 —— **已发布的会被跳过**，不会覆盖你正在改的新版本
- **分享面板打开即显示已有链接**：数据预先缓存，不会先空一下再跳出来
- **分享有效期**：1 小时 / 1 天 / 7 天 / 30 天 / 永久，到期自动失效
- **删除自动清理**：文件或文件夹被删除后，指向它的分享链接会**自动从列表移除**
- **退出登录**：右上角一键清除登录态

> 上传文件夹说明：目录结构原样保留（含空文件夹）；系统垃圾文件（`.DS_Store`、`Thumbs.db`、
> `desktop.ini`、`__MACOSX/`、AppleDouble `._*`）会自动跳过；同名文件会被**覆盖**；
> 触屏设备（手机/平板）上不显示该按钮 —— iOS Safari 不支持选择文件夹，这种情况请用多选文件上传。

## 🖥️ 宽屏布局

主区域**铺满整个窗口宽度**，没有任何 `max-width` 居中限制。所以：

- 侧栏永远贴在窗口左边缘，**左侧不会出现一条灰带**
- 顶栏的标题与侧栏的「文件管理」「搜索框」在同一条竖线上（都从 14px 开始）
- 文件越多、名字越长，越能用满屏幕宽度

> 早期版本给主区域设了 `max-width:1560px` 并居中，结果视口一旦超过 1560px
> （1600 上有 20px、**1920 上有 180px**），侧栏就被居中的边距推离左边缘，
> 而顶栏仍是全宽 —— 两者对不齐，左侧就多出一条灰带。现在去掉了这个上限。
> 已在 1080 / 1366 / 1440 / 1600 / 1920 / 2560 六种宽度下逐项验过对齐。

## 📏 高度链：文本区为什么能铺满整屏

编辑器里的文本区会**撑满整个可用高度**，而不是"只有内容那么高"。这靠一条从根到叶贯穿的 flex 链：

    body        height:100vh; display:flex; flex-direction:column
     └ .layout  flex:1
        └ main  flex:1; display:flex; flex-direction:column
           └ .wrap  flex:1; display:flex; flex-direction:column
              └ #edt  flex:1            ← 文本区

**任何一环断了**，高度就退化成"由内容决定" —— 打开一个只有两行的文件时，整页高度只够那两行，
文本框下面自然空出一大片。

移动端最容易踩这个坑：为了改成"整页滚动"，很容易顺手写成下面这样，把整条链砍断：

```css
/* ❌ display:block 之后，.layout / main 不再是 flex item，flex:1 全部失效 */
@media(max-width:900px){
  body{display:block;height:auto;overflow:auto}
  .layout{display:block}
  main{height:auto}
}
```

正确做法是**只改滚动方式，不动 flex 方向**：

```css
/* ✅ 保留列方向 flex，只把"定高一屏"换成"至少一屏高" */
@media(max-width:900px){
  body{display:flex;flex-direction:column;height:auto;min-height:100vh;overflow:auto}
  .layout{display:flex;max-width:none}
  main{height:auto;overflow:visible}
}
```

`min-height:100vh` 保证"至少一屏高"，`overflow:auto` 保证内容长时整页滚动 —— 这两件事并不冲突。
`main` 去掉 `height:100%` 之后仍是 `.layout` 的 flex item，会被 `align-items:stretch` 撑满。

另外编辑器**不留**那两块底部空白：桌面列表页的 60px 呼吸空间、移动端为批量条预留的 72px。
它们在编辑器里用不上，只会让人觉得"没铺满"：

```css
#viewEdit{padding-bottom:14px}                                   /* 桌面 */
@media(max-width:900px){ #viewEdit{padding-bottom:12px} }        /* 手机 */
```

> 这件事是**量出来的，不是看出来的**：打开一个只有两行的文件，量
> `视口高 − 状态栏底边 − wrap 的 padding-bottom`，这个值应该 ≈ 0。
> 实测 1440×900 下文本框 767px、1024×620 下 451px、390×844 下 **639px**（改之前只有约 350px），
> 三种尺寸底部浪费都是 0px；换成 300 行的长文件后文本框高度仍是 805px（内容 6656px 在框内滚动），不会被正文顶大。

## 📐 侧栏宽度：拖拽 / 一键自适应

目录树的文件名被省略号截断，根本原因是侧栏以前写死 256px。现在有三种调法：

| 做法 | 说明 |
| --- | --- |
| **拖分隔条** | 左栏和右栏之间那条细缝就是手柄，按住左右拖即可（200 ~ 620px，超界自动夹住） |
| **双击分隔条** | 自动量出目录树里最长的那个文件名，把侧栏撑到刚好装下它 —— 一键解决"名字看不全" |
| **「目录」右侧的双向箭头** | 和双击等效，更容易被发现 |
| **键盘 `←` `→`** | 手柄获得焦点后微调 12px（按住 `Shift` 是 40px），`Home` 回到默认 256px |

宽度存在浏览器本地，下次打开还是你调的宽度。移动端是抽屉式侧栏，手柄自动隐藏。

> 「自适应」量的是**每一行真正需要的宽度**（行内其它部件 + 完整文件名 + 该行缩进）取最大值，
> 所以嵌套很深的子目录也能一次算准，不会撑过头。

## ↕️ 列表排序

| 排序字段 | 怎么用 |
| --- | --- |
| **名称** | 点表头「名称」，或工具栏下拉选「名称」 |
| **类型** | 点表头「类型」，按扩展名分组（`md` → `py` → `txt` …） |
| **大小** | 点表头「大小」，第一次点默认**从大到小**（找大文件最常用） |
| **修改时间** | 点表头「修改时间」，第一次点默认**从新到旧** |

- 表头上有 `↑` / `↓` 箭头指示当前排序；**再点一次同一列就切换升降序**
- 工具栏右上角的下拉与方向按钮和表头**双向同步**（手机上表头会隐藏，用下拉即可）
- **文件夹永远排在最前**并按名称排（它们没有大小和时间可比）
- 排序偏好会记住，下次打开还是它

> 实现上有个取舍：**R2 的 `list` 不支持排序**，所以要按大小/时间/类型排，服务端必须先把整个目录列全、
> 排好序、再按偏移切片分页。代价是每次列目录都要读完这个目录（本来就很快，一次 list 调用），
> 换来的是**跨页拼接后顺序仍然全局正确** —— 不会出现"第一页最大的是 A，翻到第二页又冒出比 A 更大的"。

## 🖱️ 框选批量选择

和文件管理器一样：**在列表区域按住鼠标拖出一个蓝色选框，框到的行会被批量勾上**。

| 操作 | 效果 |
| --- | --- |
| 直接拖 | 重新框选（原来的选择被替换） |
| `Ctrl` / `Shift` + 拖 | 追加框选（保留已选的） |
| `Shift` + 点击勾选框 | 从上次点到这次之间**整段连选** |
| 全选本页 / 取消选择 | 底部批量条上的按钮 |

细节处理：

- **4px 抖动阈值**：拖动距离不到 4px 就当成普通点击，点文件名照常打开、不会误触框选
- 拖动时禁用文本选中（否则会选到一堆文件名文字），松手立刻恢复
- 拖动过程用 `requestAnimationFrame` 限流，几百行的目录也不会掉帧
- **只对鼠标生效** —— 触屏上按住拖动是滚动页面；移动端改用「长按进多选」，见下节
- 选框内判定是"矩形与行"的相交检测，斜着拖、往上拖都对

## 📦 打包下载：文件夹和批量下载

单文件下载之外，文件夹也能整个打包带走，选中多项还能一次打包。

**三个入口**：

| 入口 | 效果 |
| --- | --- |
| 文件/文件夹 **右键 → 打包下载** | 立刻打包这一项 |
| **勾选多项 → 底部「批量下载」** | 打包所有选中的文件**和**文件夹 |
| 单个文件的「下载」 | 仍是原来的直连下载（不打包，浏览器原生行为） |

**打包出来的 zip 里目录结构会保留** —— 打包 `资料/` 得到的是 `资料/子目录/a.txt`，
而不是把文件全平铺在根目录。

几个特意处理过的细节：

| 场景 | 处理 |
| --- | --- |
| 同时打包 `a/` 和 `b/`，两边都有 `same.txt` | 条目名保留顶层目录（`a/same.txt`、`b/same.txt`），**解压不会互相覆盖** |
| 打包单个文件夹 | 去掉它的顶层目录名，zip 更干净 |
| 打包单个文件 | 只取文件名，不带任何目录 |
| 同时勾选「资料」和「资料/笔记.txt」 | 自动去重，同一路径只打一份 |
| 文件夹里有空子目录 | **空目录也会出现在 zip 里**（ZIP 用 `/` 结尾、size=0 的条目记录），解压后那层目录还在 |
| 文件名里有 `../` | 打包前清掉路径穿越片段，不会写到 zip 外面 |
| 请求太快撞上每分钟限速 | 自动退避重试（尊重 `Retry-After`），实在拿不到会明确提示「等一分钟重试」而不是静默丢文件 |
| **打包空目录** | **允许下载**，弹窗会说明「这些目录里没有文件，只能打包出空文件夹」，并解释空目录本身可下载（保留目录骨架有用）；zip 里确实会带上那个空目录 |

> 空目录不会被拦成「无法下载」—— 备份项目骨架时保留空文件夹是有意义的。
> 只是提前说清楚「拿到的是空文件夹」，免得用户以为压缩包坏了。

**三个上限**（因为内容要先在浏览器内存里拼好再交给浏览器保存）：

| 上限 | 值 | 超出时 |
| --- | --- | --- |
| 文件数 | **300 个** | 弹窗里如实告知「已达上限，本次只打包一部分」，其余请分批 |
| 空目录条目 | **1000 个**（所有选中项累计） | 同上 |
| 合计体积 | **200MB** | 同上 |

> 目录条目为什么也要封顶：ZIP 的中央目录用 16 位存条目数，**总数超过 65535 整个压缩包会损坏**。
> 单次打包的目录数有 300 上限，但多选时是各目录的条目相加，所以另加了一个总量封顶。
> 目录条目本身不占体积（size=0），1000 个只有约 88KB。

**为什么不放在服务端打包？** Worker 只有 10ms CPU / 128MB 内存，真在服务端压 zip 会稳定超时；
而浏览器有整台机器的内存。ZIP 也在浏览器端生成，用的是手写的 store 模式（不压缩），
不引入任何第三方库 —— 全部实现只有 CRC32 + 四个固定头，实测 5MB 内容打包耗时约 0.8 秒。

> store 模式不压缩，所以 zip 体积和原始文件总和基本一致。好处是 CPU 极低、
> 什么文件类型都能装（包括已经是压缩包的）；代价是文本文件的体积不会变小。

## 📱 移动端怎么多选：长按

**先回答一个常见疑问：手机上为什么不干脆也做拖框？**

因为手指按住拖动**天生就是滚动页面**。硬做拖框会和滚动抢同一个手势，结果是
"想滚页面却在选文件"或者"想选文件却在滚页面"，两个都用不好。所以移动端换了一条路：

| 方式 | 怎么做 |
| --- | --- |
| **长按一行**（主入口） | 按住任意一行约 0.4 秒 → 进入多选模式，这一行立即被选中（支持的机型会轻震一下） |
| **多选模式下点行** | 点任意一行就是**勾选 / 取消**，不会再打开文件 |
| **直接点复选框** | 复选框在触屏上放大到 **21px**。它是"多选"的**常驻可见入口**，不想长按就挨个点它 |

> **为什么每行没有一个「多选」按钮？**
> 因为那种按钮和「长按整行」是**完全同一套机制**（都是"进模式 + 整行都是热区"），
> 加进去只是重复，还会把每行操作区从 6 个按钮挤到 7 个（手机上本来就挤）。
> 而"能多选"的**常驻可见入口**其实一直都有 —— 就是每行行首那个复选框，
> 它提供的是另一种交互（瞄准点选），和长按的"不用瞄准"互补。
> 所以最终只留两种：**点复选框** / **长按整行**。长按没有可见按钮，
> 靠**首次进列表时提示一次**来告诉用户（只提示一次，之后不再打扰）。

**怎么退出**：把选中项一个个取消掉，归零时**自动退出**；或者按底部批量条上的「完成」。
多选模式下不需要"先退出再操作"——底部的「批量移动 / 批量删除」直接可用。

手机上底部批量条会变成**通栏 + 按钮等分**，不再是桌面那种挤在中间的小黑条。
「全选本页」按钮会随状态变成「取消全选」，所以「先全选、再取消掉不要的那几个」这种
"反选"用法也能走通 —— 但它只是备选，逐项点选才是主路径。

几个必须处理的细节（不然功能会时灵时不灵）：

- **`touch-action: pan-y`** —— 行只拦截横向手势，纵向滑动照常滚页。
  手指一旦划动，浏览器会发 `pointercancel`，长按计时器随之取消，**不会把滚动误判成长按**。
- **`-webkit-touch-callout: none`** —— 挡掉 iOS 长按弹出的「拷贝 / 查询」系统气泡。
  少了这一条，长按到一半会被系统菜单抢走，用户以为"长按没反应"。
- **长按后补发的那次 click 要被吞掉** —— 手指抬起时浏览器还会补一次 click，
  它正好落在被长按的那一行上，会被"多选模式下点行"接走，**把刚选中的行又取消**
  （现象就是"长按了但没选上"）。所以设了一个很短的时间窗口吞掉它，
  且**只吞被长按那一行的、且没点在按钮上的** —— 否则你长按后紧接着点「重命名」也会变成点了没反应。
- **长按检测不能排除 `<a>`** —— 手机上一行里大部分面积就是文件名那个链接，
  排掉它等于"长按文件名没反应"。真正要排除的只有按钮 / 输入框 / 操作区这些控件。

## 📱 手机上的"位置感"与返回键

**顶栏面包屑**：手机上会把站点标题收起来，把那块位置让给路径面包屑（`根目录 / 笔记 / 项目`）。
每一级都可点，长路径横向滑动即可 —— 不必为了看"自己在哪一级"去开左侧抽屉。

**编辑器里的路径条**：编辑文件时工具栏上会显示这个文件的完整路径（`根目录 / 笔记 / 说明.md`）。
目录部分是真链接，**点一下直接跳到那一级的列表**，不用先退回列表再一层层点进去。

**返回键 = 回上一级目录，不是退出网站**：切换目录会写进浏览器历史（`pushState`），
所以手机的系统返回手势 / 浏览器返回键都会**退到上一级目录**。

> 以前用的是 `replaceState` —— 历史里永远只有一条记录，用户一按返回就直接离开整个网站，
> 想回上一级只能去开左侧抽屉。这是移动端最典型的"用起来就是别扭"的点。

两个容易踩的实现细节：

- **首次加载只能用 `replaceState`**。本次页面导航本身已经产生了一条历史记录，
  首屏再 `push` 一条就会出现两条 URL 完全相同的记录，用户按返回看着像"没反应"。
  判断方式：`history.state == null` 说明是首次。
- **`popstate` 里回填状态时不能再 push**，否则点一次返回会凭空多出一条历史，
  变成"怎么按都退不出去"。所以 `load(path, noHist)` 带了个"只替换、不新增"的开关。

## 📲 PWA：装到手机桌面

这个站点现在是一个合格的 PWA —— 在手机浏览器里：

| 平台 | 怎么装 | 装完什么样 |
| --- | --- | --- |
| **Android**（Chrome / Edge） | 菜单 →「安装应用」或「添加到主屏幕」（部分浏览器会自动弹安装横幅） | 独立窗口运行，出现在桌面和应用列表里 |
| **iOS**（Safari） | 分享按钮 →「添加到主屏幕」 | 全屏运行、无地址栏、状态栏样式跟随系统 |

三个组成部分，全部**动态生成、不引入任何二进制文件**：

- **图标** —— `/icon/192.png`、`/icon/512.png`、`/icon/180.png`（apple-touch-icon）按需用代码现场画出来
  （琥珀色圆角方块 + 三道"文本线"，和应用 logo 同一套配色），支持任意尺寸（16~1024），
  线条画在内 30%~70% 的安全区里，同时满足 Android 的 maskable 圆形裁切
- **manifest** —— `/manifest.webmanifest`，`display: standalone`、主题色与背景色、三个尺寸的图标
- **Service Worker** —— `/sw.js`

**关于 Service Worker 的取舍，值得说明：**

SW **只做两件安全的事**：① 图标和 manifest 走缓存优先（省流量，离线也能拿到）；
② 页面导航请求失败（断网）时给一个像样的"当前离线"页，而不是浏览器默认的恐龙页。

SW **绝不缓存页面和 API 响应** —— 页面 HTML 带着每次刷新都不同的 CSP nonce 和登录态，
缓存重放既会让 CSP 配对失效，也可能把"别人登录过的状态"留在共享设备上。
所以断网时你看到的是干净的提示页，而不是一份可能过期/错乱的旧界面。

> 想要"离线读已下载的文件"这类真离线能力，Web 端受 iOS 7 天缓存清理和配额限制，
> 这属于上一节说的 Flutter 混合方案的地盘，PWA 不硬做。

## 🎨 渲染层：按类型自动选择怎么显示

打开文件的出口不再是「一律塞进 `<pre>`」，而是**一张分派表**：按扩展名（必要时参考 MIME）
挑一个渲染器。核心约定有两条：

1. **所有渲染器都先做 HTML 转义**，只输出程序自己生成的标签 —— 没有原始 HTML 透传，杜绝 XSS；
2. **任何解析失败一律退回纯文本**，所以最差情况就是原来的效果，**不存在"改完之后某个文件打不开"**。

| 文件类别 | 扩展名 | 显示成什么 | 右上角可切源码 |
| --- | --- | --- | --- |
| Markdown | `md` `markdown` `mdx` `rst` `org` | 标题/表格/代码块/任务列表/引用渲染成网页，**自动生成目录** | ✅ |
| JSON 系 | `json` `json5` `jsonc` `jsonl` `ndjson` `geojson` | **可折叠的树**，显示子项数量；`jsonl` 逐行解析 | ✅ |
| 表格 | `csv` `tsv` `psv` | **表格视图**，首行当表头，**点表头排序** | ✅ |
| 代码 | `js` `ts` `py` `go` `rs` `java` `c/cpp` `css` `sh` `sql` `yaml` `toml` … | **语法高亮**（关键字/字符串/注释/数字分开上色） | ✅ |
| 其它全部文本 | `txt` `log` `srt` `diff` `pem` 等剩余 100+ 种 | **纯文本兜底**（和以前完全一样） | — |
| 图片 | `png` `jpg` `gif` `webp` `avif` `svg` | 灯箱查看，可缩放 / 旋转 / 点击放大 | — |
| 音频 / 视频 / PDF | `mp3` `mp4` `webm` `pdf` … | 内嵌播放器 / PDF 阅读器 | — |
| 真二进制 | `zip` `exe` `docx` … | 保持直接下载 | — |

**为什么渲染能做成"零服务端开销"**：解析与高亮全部在**浏览器里**跑，Worker 那段代码一行没变，
仍然只是把文件字节取出来。所以 Worker 的 CPU 时间、R2 存储、R2 操作次数**都没有增加**，
唯一变化是页面脚本大了约 60KB（部署包上限 3MB）。

Markdown 渲染有一条**明确的安全边界**：不解析原始 HTML。写了 `<div>` 会原样显示成文字而不是变成标签，
链接只放行 `http(s)` / `mailto` / 站内相对路径（`javascript:`、`data:` 一律丢弃），图片同理。
所以即使有人往你的盘里传一个精心构造的 `.md`，也**不可能在分享页上执行脚本**。

**编辑器里纯文本的网址也会挂上图标**：不光是 Markdown，任何正文里的完整网址（`http(s)://…` 或裸 `www.…`，
后者自动补 `https://`）都会在末尾挂一个链接图标。图标是**覆盖层**（`#edHl` 里的 `#edLinkIcons`）画的，
叠在文本框上方、**不影响打字与选区**。
边界和 Markdown 一致：只认 `http(s)`（`javascript:` 之类的伪协议一律不做成链接）。
正文超过 **256KB** 时不再渲染图标，优先保证输入流畅。

> **只读分享页不挂图标**：查看器的正文用 `textContent` 原样写进 `<pre>`，不做任何加工。
> 分享页面向访客与下游程序，正文越"干净"越不容易出问题（单文件分享直链本来就是纯文本响应）。

**网址不染色、不铺底纹，只在末尾挂一个图标** —— 这条别改回去。文本框（`<textarea>`）没法只给几个字上色，
想让网址"变蓝"就得在它上面盖一层、用白底挡住原字再画上蓝字；两层只要差半个像素（浏览器缩放、DPI、
子像素滚动、字体回退），就会露出底下的字，看起来像**网址被单独贴了一层、出现重影**。只铺底色也一样：
底色块和文字对不齐时会显得"覆盖都没覆盖上、地方全不对"。所以现在**两层都不画**，网址就是纯文本。

图标是另外一层（`#edLinkIcons`），每个网址末尾挂一个：位置靠**隐形量测层 `#edMeasure`** 量 ——
它和文本框同宽、同字体、同换行口径，用 `Range` 取"网址最后一个字符"的矩形，再换算成叠层坐标，
所以图标永远紧贴网址结尾（**不是**行尾，长句中间也一样）。这层整体 `pointer-events:none`，
只有图标本身可点，点空白处仍然是正常放光标。缓存键 = 正文 + 字号 + 换行开关，光标移动/滚动不重算。

**图标必须"小 + 抬高成上标"**：文本框的排版改不了，图标只要平着放在网址末尾，就必然压住后面那个字 ——
`https://a.com/x。后文` 这种"网址紧跟中文"的场景最明显，会跟后面的字撞在一起。所以尺寸压到 **11px**
（浅蓝 `#6aa9e0`，只有图标、不带文字），并在此基础上**再往上抬 4px** 成上标位置，从字的字身上方让过去。

**网址在第一个全角句读处截断**：只"从尾部删标点"是不够的 —— `https://a.com/x。后文` 里句号不在结尾，
整串会被当成一个网址、把后面的中文一起吃掉，图标也就跑到句子最后去了。所以匹配到之后先在
`。，；：！？、` 里第一个出现的位置截断，再走尾部的 `trimUrlEnd`。路径里的中文（`…/wiki/中文`）照旧保留。

**打开网址的两条路**，都不跟"点一下把光标放这儿"抢：桌面 `Ctrl`/`Cmd` + 点击直接打开（`linkAt()` 按光标位
判定命中）；任何设备都可以点网址末尾那个小图标（图标本身就是 `<a target="_blank" rel="noopener">`）。
普通点击永远是放光标，所以不会误跳走，也不会抢掉长按复制。（只读分享页不挂图标，见上。）

> ⚠️ **改这段代码要小心**：整个页面脚本是拼在一个**模板字符串**里的，源码里写 `\` 会被吞掉。
> 所以这里的正则用 `String.fromCharCode` / `CH_BS` 拼，结尾标点表（`URL_TAIL`）也用**字符码**建 ——
> 直接写正则字面量会悄悄变味（比如 `[.,;:!?'"\]}>]` 里的 `\]` 被吞掉后字符类提前闭合，
> 结尾逗号就再也去不掉了）。**字符串里的转义同理**：`split('\n')` 会被吞成真换行、
> 把字符串字面量从中间劈开（症状是整页 JS 报 `Invalid or unexpected token`），必须写成 `split('\\n')`。
> 改动后务必跑 `.workbuddy/tests/check.mjs` 与 `browser.mjs`（前者专门查这类"被吞"事故）。

## ✂️ 编辑与分享分离：草稿、发布、撤回

管理端改文件和访客看文件，是**两件必须分开的事**。你可能改到一半觉得不满意、
或者里面有些内容暂时不想给访客看 —— 这时候分享页就该**纹丝不动**。

所以存储上分成了两棵树，物理隔离，不是靠界面藏：

| | 存哪儿 | 谁在读 | 什么时候变 |
| --- | --- | --- | --- |
| **草稿树** | R2 的 `d/` 前缀 | 只有管理端 | **随时自动保存**（停手 1.5 秒） |
| **已发布影子树** | R2 的 `__pub__/` 前缀 | **只有分享页** | **只在你点「发布」时** |

### 编辑器里怎么用

- **改就完了，不用惦记保存**。停手 1.5 秒自动存；文本框失焦、切到后台标签页、关页面时各再兜一次。
  连续快速保存会**排队串行执行**，不会出现"后发的请求先返回、把新内容盖成旧内容"
- 工具栏上**没有「保存」按钮了**，只有 **「发布」** —— 这个按钮的语义就变成"我确认这版可以给访客看了"
- **文件没有任何分享链接时，「发布」是灰的**：点了也没有任何链接会指向它，等于白往影子树里拷一份。
  这时按钮的悬停提示会说明原因，旁边的 **「分享」同时提成蓝底主按钮** —— 唯一有意义的下一步就是先建链接。
  建完（或取消掉最后一条）链接，按钮**当场**跟着变，不用刷新页面
- **在已分享的目录里编辑文件，按钮照常可点**：这个文件确实会出现在目录分享页上，发布是有意义的
- 点「发布」会先把当前内容存一遍，再复制到影子树
- 改过、但还没重新发布的文件，状态栏和分享列表会标 **「· 待发布」**，提醒你链接目前给访客看的是旧版
- 分享出去的目录，**改里面的文件也一样**：点发布就把该文件的最新版发出去，
  目录的分享链接里，这个文件立刻变成新内容

### 分享面板里怎么用

每条分享后面有 **「发布」** 和 **「撤回」**：

- **发布**：把当前版本复制到影子树，分享页立刻更新
- **撤回**：把影子树副本删掉，**分享页暂时 404**；但**草稿内容一个字都没少，链接也还在**，
  列表里标成「待发布」，随时能发回来
- **全部发布**（分享管理里）：给老版本升级上来的存量分享一次性补发副本。
  **已经发布过的会被跳过**，不会覆盖你正在改的新版本

### 删除 / 改名 / 移动会自动同步

这几类操作都会**同时作用于两棵树**，所以分享链接不会因为你在管理端整理文件而突然失效：

| 操作 | 草稿树 | 影子树 |
| --- | --- | --- |
| 删除 | 删 | **一起删**（不留孤儿副本） |
| 移动 / 重命名 | 搬 | **跟着搬**（分享页不至于 404），指向它的分享记录同步改指向 |
| 编辑 | 改（自动） | **不动** |

### 升级到这一版

老版本只有一棵树（当时还没有影子树），所以**升级后历史分享会打不开** ——
记录还在，但内容没复制过去。打开 **分享管理** 会看到"有 N 条还没发布"，
点 **「全部发布」** 补齐即可。新建的分享则是**建完就自动发布**，链接直接可用。

### 分享页不做全文搜索

分享页的搜索框**只按文件名和目录名搜，不搜正文**。这是刻意的取舍：

- 不用为影子树再维护一份全文索引，少一处会不同步的状态
- 更重要的是**不会泄露** —— 影子树只有已发布内容，但搜索走索引的话，索引里可能混着草稿；
  只搜文件名就没有这个风险
- 管理端的搜索**仍然是全文**，不受影响

界面上也一并说清楚了，不用访客自己撞一次才知道：

| 位置 | 访客看到什么 |
| --- | --- |
| 搜索框 | placeholder 写「按文件名 / 目录搜索…」 |
| 搜索结果下方 | 「此分享页**只按文件名和目录名搜索**，不搜索文件内容」 |
| 结果分组 / 筛选芯片 | 只有「文件名命中 / 路径命中 / 文件夹」，**没有「正文命中」** |
| 索引相关的一切 | **完全不出现** —— 没有「建立正文索引」按钮、没有「未进索引」「容量已满」这些内部状态 |
| 右键菜单 | 没有「深搜此文件」（那是读全文精确匹配，访客用不了） |

> 「建立正文索引」这个按钮以前在分享页上也出现过 —— 但 `reindex` 只对管理员开放，
> 访客点了只会收到一个 403。**看得到却点不动，属于典型的死入口**，已经去掉。

## 💰 省资源：三道坎

自动保存是**高频动作** —— 用户连续改 10 分钟就能触发上百次请求。所以要省资源。
但省资源不能拿"数据可能丢、或者搜不到"去换，所以这里只动**确定是浪费**的部分。

### 第一道坎：内容没变，根本不用发请求

打开文件时，正文会被记为一份「基线」（`ed.savedText`）。每次要保存前，先把文本框内容和基线**逐字比较**：

- **一样** → 判定"用户其实没改"，**一个请求都不发**，顺手把脏标撤掉
- **不一样** → 才真的发 PUT，发完把基线推进到刚存的内容

典型受益场景（这些在旧逻辑下**每次都在白白发请求**）：

| 你做了什么 | 旧逻辑 | 现在 |
| --- | --- | --- |
| 打了个错字又删掉 | PUT 一次 | **0 次** |
| `Ctrl+Z` 撤销回原样 | PUT 一次 | **0 次** |
| 复制粘贴再撤销 | PUT 一次 | **0 次** |
| 打开文件看了眼就关掉 | 0 次 | 0 次 |

这一层比较**纯在浏览器里做**，不消耗任何 Cloudflare 配额。

### 第二道坎：防抖从 1.5 秒放宽到 5 秒

用户连续打字时，防抖计时器会一直重置，**只有真正停手才触发**。1.5 秒太短 —— 打字时的自然停顿经常超过 1.5 秒，
于是"想一下措辞"的间隙也被算成一次编辑。

放宽到 5 秒后，连续改 10 分钟的保存次数从 **~80 次降到 ~24 次**。
而"最多丢最后一次修改"的风险**一点没增加** —— 因为下面这三处仍然是**立刻静默存**：

- 文本框**失焦**（点别处、点按钮）
- **切到后台标签页**（`visibilitychange`）
- **关闭 / 刷新页面**（`pagehide`）

也就是说，"我要离开这个页面了"这种明确信号，永远不会被延迟。

### 第三道坎：省掉那次多余的目录列表刷新

保存成功后前端原本会再拉一次目录列表，就为了刷新左栏里那几个字节的时间和大小。
但内容缓存（`fileCachePut`）**已经把正文同步过来了**，这次刷新纯属重复 ——
而自动保存是高频动作，每次都多花一次 R2 `list`（Class A）不值当。

去掉之后**可见行为零变化**：左栏的元数据晚到你切目录或点刷新时自然就准了。

### 关于搜索索引：为什么**没有**省

搜索索引是这套设计里**唯一没动**的部分，因为它一动就会拿"搜不到"去换。

试过"懒更新"（保存时不碰索引，等搜索时按 mtime 补），实测下来代价太大：

| 场景 | 懒更新 | 现在（同步建） |
| --- | --- | --- |
| 改完文件**第一次**搜新内容 | **搜不到**（要再搜一次） | ✅ 立刻搜到 |
| 刚上传 100 个文件后第一次搜正文 | 只命中 **60** 个，要好几轮才补齐 | ✅ 100 个全中 |
| 旧正文什么时候失效 | 下一轮搜索之后 | ✅ 立刻 |

搜不到东西是很糟糕的体验 —— 用户不会意识到"我得再搜一次"，只会以为功能坏了。
所以宁可多花一次写索引，也要把**搜得全、搜得准、搜得即时**保住。

> 顺带说清一件事：R2 是**按操作次数**计费的，不是按写入字节。所以"索引写 400KB"和
> "索引写 12KB"在费用上**完全一样**（都是 1 次 Class A）。真正贵的是**次数多**，
> 而省次数的办法是上面第一、二道坎（不发无谓的请求），不是压字节。

### 消耗实测

100 个文件、每个 4KB 正文，连续改 10 分钟（24 次真实保存）：

| 指标 | 实测值 |
| --- | --- |
| 每次保存的 R2 操作 | **4 次**（写文件 + 写索引 + 读索引 + 探测同名目录） |
| 每次保存的索引写入 | 约 7 KB（整份重写，文件越多越大） |
| 改完第一次搜新内容 | **能搜到** |
| 批量上传后第一次搜 | **能搜到全部** |

换算成月度（每天改 2 小时 ≈ 21,600 次保存）：

| | 用量 | 免费额度 | 占比 |
| --- | --- | --- | --- |
| Class A | 43,200 | 100 万 / 月 | **4.3%** |
| Class B | 43,200 | 1000 万 / 月 | **0.4%** |
| 存储 | 400 KB | 10 GB | 0.004% |

**费用 $0。** 而且第一道坎还会再省掉一部分 —— 改完又改回来的操作一次请求都不发。

## 🔍 全文搜索：为什么它很快

> 这一节说的是**管理端**的搜索。分享页只搜文件名 / 目录名、不搜正文（见上文「分享页不做全文搜索」）。

搜索走的是 **R2 里的内容索引**（存为 `__sys__/idx.json`，一个隐藏的系统键），不是每次去翻 R2 的文件：

- **索引是同步建的**：保存 / 上传文件时**当场**把这个文件写进索引（挂 `waitUntil`，不拖慢保存本身），
  所以**改完立刻能搜到**，不会出现"第一次搜不到、再搜一次才有"的情况
- 索引写入带 **etag 条件写（乐观锁）**：并发冲突时自动重读重放，从根上杜绝"批量上传丢索引条目"的问题
  - **索引还不存在时**（首次上传、或索引文件被删）改用 `etagDoesNotMatch: '*'`，也就是 S3 的
    `If-None-Match: *` —— "仅当对象不存在时创建"。少了这一步会怎样：etag 为 null 时条件写被跳过，
    多路并发各自**无条件覆盖写**，最后一路胜出、其余静默丢失（实测 4 路并发只剩 1 条，
    且**不会自愈**，只能靠"批量上传后重建"兜底）。加上后首建并发也是 4/4 全中
- 搜索时读**一个索引文件**在内存里做正文匹配，**不读任何文件的正文**；另外补一次**只列 key 的扫描**，
  把「在 R2 里却没进索引」的文件按文件名补进来（见下）
- 结果里给出**命中上下文片段**并高亮关键词；文件名命中与正文命中分开标注
- 速度**与文件数量基本无关**（实测 100 个文件和 5000 个文件都是 0.1~0.2 秒级）
- 老部署升级无感：首次访问时旧 KV 索引自动迁移到 R2，之后删除 KV 里的旧键

> **索引只是加速层，R2 才是真相。** 搜索时会用一次 `list`（每 1000 个文件 1 次调用，**不读对象正文**）
> 把索引里缺失的文件按「仅文件名」补进结果，所以**任何文件都不会因为索引不完整而搜不到**。
> 保存文件时会同步写索引，所以正常情况下这个集合是空的；只有从控制台 / S3 / rclone
> 直接放进 R2 的文件才会落进来，点一次「重建 / 更新正文索引」即可补上正文。

**搜索框支持的轻量语法**（可混用）：

| 语法 | 作用 | 示例 |
| --- | --- | --- |
| `ext:后缀` | 只搜某一类型（可带点） | `ext:md 配置`、`ext:log timeout`、`ext:md`（单独用=列出该类型全部文件） |
| `path:目录` | 只搜某目录下的内容 | `path:笔记 密码` |
| `"整词"` | 双引号包裹 = 整词匹配 | `"cat"` 不会命中 `category` |

**目录名命中会带出文件夹本体**：搜「fniao」时，结果第一位是 **fniao 文件夹**（标「文件夹」，点击直接进入该目录）；
目录下的文件照常列出，但标签如实标为 **「路径」**（目录名带出来的命中）——与真正的「文件名」命中区分开。
排序依次为：文件夹 > 文件名命中 > 路径命中 > 正文命中。

不带语法时就是普通搜索：**大小写不敏感的子串匹配**（搜「菜鸟」能命中「我的菜鸟笔记」）。
不做分词，所以搜「鸟笔」也会命中「菜鸟笔记」—— 对个人文本盘这属于可接受的取舍。

**搜索的交互（本版新增）**：

- **搜索历史**：搜过的词自动记在浏览器本地（`localStorage`，不上传、不同步），
  点搜索框即弹出历史下拉，**↑↓ 选择、Enter 确认**，也可以一键「清除搜索记录」。
  只有输入**停手 1.4 秒**的词才落库 —— `f` / `fn` / `fni` 这类半成品不会把历史刷满
- **结果列表键盘导航**：光标不在输入框时，**↑↓ 在结果间移动（自动滚进视野）、Enter 打开、Esc 取消选中**，
  鼠标和键盘两条路都能走
- **清空搜索框不丢结果**：清空输入或点「在目录中显示」后，侧栏顶部留一条
  **「返回搜索结果：xxx」**，一键回到上一次的结果，不用把词重新敲一遍
- **「只在当前目录内搜索」开关**：在子目录里搜索时，勾上就把范围收进当前目录
  （等价于自动补一个 `path:`）；框里**手打的 `path:` 优先**，不会被复选框悄悄改掉
- **多关键词区分着色**：AND 搜索时每个关键词换一种底色（三色轮换），
  一眼看出"哪个词命中了哪一段"；重叠区间合并、不会嵌套出脏 DOM
- **结果分组 + 筛选芯片**：结果顶部一排芯片「全部 / 文件名命中 / 路径命中 / 正文命中 / 文件夹」，
  点一下只看那一类。筛选是**服务端过滤**（分页、总数、"还有 N 条"一起变，不会只筛当前页）；
  「全部」视图下结果按类型分组，**分组先后跟随相关度**（文件夹条目 → 文件名命中 → 路径命中 → 正文命中），
  不会把服务端排好的名次打乱（搜目录名时文件夹仍排在最前）
- **信息层级重整**：「深搜此文件」不再挤在结果行里，收进 **⋯ / 右键菜单**（菜单会自动带上当前搜索词）
- **打开就把关键词点亮**：从搜索结果打开文件时，**正文里所有命中当场高亮**，
  查找栏自动带出搜索词并显示「1 / N 处」，**上一个 / 下一个**逐个走，
  不用再靠肉眼一行行找。多关键词各用一种底色（与侧栏结果同一套色）；
  这时候查找栏只留「查找框 + N 处 + 上一处 / 下一处」，**替换控件收起**
  —— 这个动作是"看在哪"，不是"要替换"；自己按 `Ctrl+F` 打开查找栏时替换控件照旧给全。
  命中只在文件名 / 路径上时不会留下一个写着"无匹配"的空查找栏，静默收回。
  **仍然不抢焦点**（手机不弹软键盘）—— 只是替你把位置指出来
  （只读**分享页**暂不含此高亮，留待后续）
- **重复搜索更省**：补扫 R2 的清单有 **60 秒内存缓存**，窗口内换词再搜不再重扫 R2；
  经本 Worker 的上传 / 删除 / 改名 / 移动会**立即让缓存失效**，所以新文件马上搜得到
  （实测 3000 个文件：首次搜索 4 次 `list`，60 秒内再搜 **0 次**）

**打开文件更快（三级加速）**：

1. **两个请求并行**：点左侧树里的文件不再"先刷新列表、等完成再读文件"（那是串行的两次网络往返），
   现在读文件与刷新列表同时发出，打开延迟减半
2. **内存缓存 + 后台校验**：打开过的文件内容留在浏览器内存里（LRU，按字节封顶 8MB / 最多 30 个）。
   再次打开**点击瞬间就有内容（0 等待）**，同时后台拿 `ETag` 校验一次：没变就静默，
   真变了才热替换并提示"该文件已在别处更新"——快，但不会看到过期内容。
   保存 / 删除 / 改名 / 移动 / 覆盖上传都会让对应缓存失效
3. **悬停预取**：桌面端鼠标在文件名上停 130ms，内容就已经在后台取回来了 ——
   **连第一次打开都是瞬时的**。触屏设备自动跳过，只预取小文本（≤256KB），最多 2 个并行

> 实测：前端渲染 669KB 的大文件也只要约 17ms —— 浏览器侧从来不是瓶颈，
> 慢的是"每次都要走一趟网络去 R2 取"。上面三条就是把这一趟尽量省掉。

**深搜带行号定位**：对「可能截断」的文件点「深搜此文件」，结果不再只是一个数字 ——
弹窗标题给出**全文命中总数与命中行数**，列表里逐行列出**行号 + 该行命中片段**，
片段**以命中位置为中心截取**（不是行首截断），所以关键词一定会被高亮；同一行有多处命中时右侧标出「N 处」。
**点击任意一行直接打开文件并跳到那一行**（≤512KB 的文件才生成行号列表，最多 200 行；更大的文件只给总数，省 CPU）。

索引的取舍与兜底（重要）：

| 情况 | 表现 |
| --- | --- |
| 文件 ≤ 8KB | 正文**完整**进索引，搜得到 |
| 文件 > 8KB | 只索引前 8KB，结果里标 **「可能截断」**，并提供 **「深搜此文件（读全文精确匹配）」** 按钮 |
| 二进制 / 图片 / 视频 / 超过 512KB 的大文件 | 不索引正文，**只按文件名**参与搜索 |
| 索引里没有正文的文件（老文件、从控制台/S3/rclone 直接放进 R2 的、超配额降级的） | 搜索时按**文件名/路径**照常搜到（不读正文所以不会漏文件）；点 **「重建 / 更新正文索引」** 补上正文 |
| **文件夹批量上传** | 并发写索引曾会互相覆盖丢条目（已用 R2 条件写根治，含索引首建时用 `etagDoesNotMatch:*` 原子建键）；批量上传结束后前端**仍会自动分批重建一次索引**兜底 |

> 「重建 / 更新正文索引」按钮**常驻在搜索结果下方**（不再只在索引为空时出现），
> 所以索引一旦不完整随时可以一键补齐；重建过程中即使有人在上传，本批也会**自动重读重放**而不是整批失败。
> 日常使用基本用不到它 —— 保存文件时会同步写索引，缺的通常只是从控制台直接塞进 R2 的那批文件。

> 索引正文总量默认上限 **1MB**（`INDEX_TEXT_CAP` 可调，且**最多放宽到 1.5MB**）。原因是免费版 Worker 单次请求只有
> **10 毫秒 CPU**，`JSON.parse` 一个过大的索引会把它吃掉。配额快满时单文件正文片段会**自动缩短**
> （8KB → … → 512 字符，渐进降级而不是整段丢弃），配额耗尽后才退化成"只按文件名搜索"，
> 且搜索结果里会**明确提示容量已满**。索引迁到 R2 后，不再占用 KV 的写配额。

## 🔁 上传时的同名文件怎么处理

判断「是不是同一个文件」不看内容，而是看 **相对路径 + 大小 + 原始修改时间** —— 这也是各类同步工具
（rsync / Syncthing / 坚果云）的默认做法：算内容哈希最准，但几百 MB 起步就要几十秒，体验很差。

上传前会先取一份云端清单（只含路径、大小、上传时记下的原始修改时间，不读内容），然后把要传的文件分三类：

| 分类 | 判定 | 默认行为 |
| --- | --- | --- |
| **完全一致** | 路径、大小都相同，且记录的修改时间也一致 | 跳过（省流量），可勾选「也重新上传」强制重传 |
| **同名但可能不同** | 路径相同，但大小或时间不一致 | 由你在弹窗里决定 |
| **云端没有** | 路径不存在 | 直接上传 |

弹窗里三选一：

- **跳过**（默认，最保守）：云端已有的一个都不动，只补新文件
- **覆盖**：用你上传的替换掉同名文件（「完全一致」的仍会自动跳过，省流量）
- **都保留**：新上传的自动改名为 `名字 (1).txt`、`名字 (2).txt`，云端旧文件原样留着

> 说明两点：
> 1. **旧文件没有时间记录**（这个功能上线前传的），只能按大小判断，会被归到「完全一致」。
>    如果你在意，可以选「跳过」保守处理，或者先删掉云端旧的再传。
> 2. 想绝对安全就选「跳过」—— 它永远不会动云端数据。

### 关于「上传的文件被修改过」

你的顾虑是对的：**同名不等于同一份内容**。所以这里不做"名字一样就覆盖"这种粗暴判断，
而是先按大小/时间筛一遍，把不确定的（大小或时间对不上的）单独列出来让你决定。
真要严格的字节级一致，只能算哈希 —— 需要的话可以再加，但代价是上传前要先本地读完整个文件夹。

按常见文件管理器的习惯来设计的，**折叠着也能看清里面有没有东西**：

| 看到的样子 | 含义 |
| --- | --- |
| 文件夹名后面有灰色小数字 `12` | 这个文件夹里直接放着 **12 项**（子文件夹 + 文件），点三角就能展开 |
| 文件夹前**没有三角**、数字是 `0` | **空文件夹**，里面什么都没有 |

- 分享链接的**作用域是隔离的**：分享某个目录之后，访客的目录树与搜索都**只能看到该目录内部**，看不到别的地方

> 目录树一次最多返回 **12000 个对象**、**单个目录最多 500 个文件**，
> 超出时会在树里提示"还有 N 个文件未列出，请在右侧查看"（右侧列表始终完整）。

### 🔤 编码自动识别

以前用记事本或老软件存的中文 txt 多为 **GBK**，按 UTF-8 打开就是一屏乱码。现在会自动判断：

| 顺序 | 判据 |
| --- | --- |
| 1 | **BOM** 优先：UTF-8 BOM / UTF-16 LE / UTF-16 BE 直接命中 |
| 2 | **严格 UTF-8 试解**：能成功解出就是 UTF-8 |
| 3 | 失败则在**前 64KB 采样**上试 GB18030 / Big5 / EUC-KR / Shift-JIS / Windows-1252，取**替换字符最少**的那个 |
| 4 | 用胜出的编码整篇解码，并**去掉 BOM** |

- 采样是为了控 CPU（免费版单次请求只有 10ms）
- 打开时状态栏会提示「原编码 gb18030，保存后将转为 UTF-8」，**保存一律写 UTF-8**
- 分享页也会做同样的转换，所以老文件分享出去别人看到的也是正常中文

## ⚡ 性能与成本

| 优化 | 做了什么 | 效果 |
| --- | --- | --- |
| **ETag / 条件请求** | `read` / `download` / `raw` 都返回 `ETag`，请求带 `If-None-Match` 且内容未变时直接 **304** | 省下响应体传输与（文本的）转码 CPU |
| **边缘缓存** | 公开分享内容走 `caches.default`，命中时**完全不碰 R2** | 热门分享**省 R2 Class B 读**；取消分享后旧链接不再命中 |
| **大目录分页** | 一次最多取 300 项，剩下的给「加载更多」按钮 | 上千个文件的目录不再一次性灌进 DOM |
| **分页 + 排序兼容** | 服务端先列全目录、排序，再按偏移切片 | 跨页顺序全局正确 |
| **断点续传 / 分片上传** | 超过 8MB 的文件走 R2 multipart，**单个分片失败只重传那一片**；上传会话记在 KV 里 | 100MB 的文件不再"断一次从头来"，**已传分片会保留** |
| **并行上传 + 退避** | 文件夹上传 4 路、多选上传 3 路并发；撞到 429 会尊重 `Retry-After` 退避重试 | 上传几百个文件时不会自己把自己限死 |
| **索引替代扫描** | 正文匹配走索引，不做 N 次 R2 读；只补一次 `list` 拿文件名（每 1000 个文件 1 次） | 搜索耗时与文件数基本无关，同时不会因索引不完整漏文件 |
| **重建索引批大小自适应** | 每批处理多少个文件由**服务端按索引体积**算：索引小就大批（省网络往返），索引大了就小批（避开 1102） | 重建 1200 个文件的等待从 1500ms 降到 550ms；索引满载时也不会因为单轮太重被 Cloudflare 打断 |

关于分片上传有个**反直觉的点**：R2 的 `CreateMultipartUpload` 与 `UploadPart` **都算 Class A 操作**，
小文件走多段反而更贵。所以前端设了阈值 —— **只有超过 8MB 才走多段**，其余仍是一次 PUT。

## 🔐 安全说明（重要，请读一遍）

| 你设置了什么 | 谁能进管理页 |
| --- | --- |
| 只设 `ADMIN_UUID` | **任何知道那串路径的人**。`ADMIN_UUID` 等于密码，而且会留在浏览器历史/分享记录里 |
| 再设 `PASSWORD` | 需要额外输入密码。「退出」按钮只在设了 `PASSWORD` 后出现（没有会话就无所谓退出） |

所以：**只要这个站点不是纯自用、或者可能被别人碰到链接，就务必设上 `PASSWORD`。**

已做的防护：

- 登录态的 Cookie 是 `HttpOnly + Secure + SameSite=Lax`，脚本读不到
- **登录失败限速**：同一 IP 10 分钟内错 8 次就锁定，期间即使密码正确也拒绝（防爆破）
- **改 `PASSWORD` 会立即让所有旧登录态失效**——怀疑泄露就改密码
- 分享链接一律**只读**，访客无法写入、删除，也无法再创建新的分享
- 所有路径都经过归一化，`../` 会被折叠，无法跳出存储根目录
- **CSRF 防护**：所有写操作（POST/PUT/DELETE）校验 `Origin`，来自别的站点的请求直接 403
- **CSP 内容安全策略**：页面只允许带随机 nonce 的内联脚本，外部脚本一律不加载（每次刷新 nonce 都不同）
- **安全响应头**：`nosniff`（禁 MIME 嗅探）、`X-Frame-Options: DENY`（防点击劫持）、`noindex`（不被搜索引擎收录）
- **恶意文件沙箱**：别人上传的 HTML / SVG 直链**不会按原类型裸奔**（HTML 走壳页面 + `?doc=1` 真文档 + `script-src 'none'`，SVG 按纯文本）；预览 HTML 走的是**不带 `allow-same-origin` / `allow-scripts` 的 sandbox iframe**，
  上传的脚本无法在本站源上执行、也碰不到 Cookie；连页面想引用的资源都只放行本分享目录内的**被动类型**（CSS / 图片 / 字体，不含 JS）
- **Markdown 不放行原始 HTML**：`.md` 里的 `<div>` / `<script>` 会被原样显示成文字，链接只放行 `http(s)` / `mailto` / 站内相对路径
- **接口限速**（见下方两个环境变量），防恶意刷流量

> 为了做图片 / 音视频 / PDF 预览，CSP 的 `img-src` / `media-src` / `frame-src` 放行了 `blob:`。
> 内容都是通过 `URL.createObjectURL` 从同源接口取的字节，**不引入任何外部域**；
> `object-src` 仍然是 `'none'`。如果不想要这个放宽，删掉 `appHtml` 里 CSP 字符串中的 `blob:` 即可
> —— 代价是媒体预览会失效（文本类渲染完全不受影响）。

### 🚦 防刷流量：两层限速 + 一条建议

| 层 | 说明 |
| --- | --- |
| Worker 内置（默认开） | 每 IP 每分钟 **240** 次请求（`RATE_LIMIT`）、分享文件直连每 IP 每分钟 **60** 次（`DOWNLOAD_LIMIT`），超了返回 429 |
| 例外：管理端写操作 | 上传文件/建目录（`/{ADMIN_UUID}/api` 的 PUT/POST/DELETE）**不计入**通用限速 —— 上传文件夹本来就是几十上百个请求。它们受密码 + CSRF 保护；**读取**与访客分享面仍然照常限速 |
| Cloudflare WAF（推荐） | 免费版自带 **1 条 Rate Limiting 规则**，在控制台对 `/*你的分享路径*/` 配"每分钟 N 次请求"，这是**跨全球生效的硬限流**，比 Worker 内置的更可靠 |

> Worker 内置的计数存在单个隔离实例的内存里，Cloudflare 会在多个节点各自计数，
> 所以它是"尽力而为"的缓冲垫；真正要挡住刷子，请把 WAF 规则配上。

还没做、需要你注意的：

- 没有登录二次验证（2FA），只靠密码

## 🔒 受保护文件夹（防止误删）

把一个文件夹标成「受保护」后，**它里面的所有文件和子文件夹，删除时都必须先输入管理员密码**
—— 给重要目录加一道"手滑保险"，防止批量删除或误点把要紧的东西清掉。

**怎么标记 / 取消**

| 方式 | 位置 |
| --- | --- |
| 新建时就上锁 | 工具栏「新建文件夹」→ 勾选 **🔒 设为受保护文件夹** |

- 列表里：受保护文件夹的**图标是和普通文件夹完全不同的金色实心文件夹 + 小锁**（普通文件夹是按层级配色的描边文件夹），
  名字后面还挂着红色 **🔒 受保护** 徽标，整行左侧有一条金色色条、行底色也带一点暖色
- 左侧目录树里：同一个金色锁图标，并带一个 🔒 小锁
- 排序时受保护文件夹始终在最前（其余文件夹仍按名称排），树和列表一致

**删除时会发生什么**

- 点删除（或批量删除）时，只要目标在受保护文件夹内，就会**先弹管理员密码框**，验证通过才真正删除
- 密码输错会提示「密码错误」并让你重输（连续 3 次失败才放弃），不会因为一次手滑就删掉
- 密码由**服务端**核对：就算绕过前端直接打接口，没密码一样 `403`，删不掉
- **取消保护**同样由服务端核对密码：不带密码或密码错误一律 `403`，标记原样保留
- 受保护的文件夹**改名、移动**后，锁会跟着走，不会丢
- 分享页（访客）看不到这个标记，也不可能触发删除

> ⚠️ 这个功能依赖环境变量 **`PASSWORD`**。没设密码的站点无法校验，受保护内容的删除会被**直接拒绝**
> （而不是"静默放行"）；**取消保护也会被拒绝**（这时前端不会反复弹密码框）。想用这个功能，请先设好 `PASSWORD`。

**移动围栏（防误搬）**

- 受保护的文件 / 文件夹**搬到普通目录，需要验证管理员密码**（防手滑；密码对了就放行，不再一刀切拦死）
- **普通文件 / 文件夹搬进保护区，也要验证管理员密码**（进了保险箱就按受保护规则约束，删除要密码）
- 搬出去之后：文件自然不再受保护（保护来自祖先目录）；**文件夹自带的 🔒 标记会跟着走**（换位置不自动解除保护，想解除再去菜单里"取消受保护"，也要密码）
- **批量移动**：整批含跨界项目时先验一次密码，密码不对**整批都不动**（原子），对了整批搬走
- **同目录改名不受影响**（标记跟着走，保护域没变）；保护区内互搬不需要密码
- 前端选目标时会**提前提示**（搬出/搬入都蓝字告知要验密码，点确定后弹框）；服务端再次强制校验（`403` + `needPw`），
  搬入/搬出口径分开提示，密码错可重输 3 次；绕过前端直接打接口也搬不走
- 未设 `PASSWORD` 的站点：跨界移动直接被拒（`noPwSet`，前端不再反复弹框）

> 范围说明：围栏管的是**删除、取消保护、移入 / 移出保护区**。**下载、预览、分享**和普通文件一样不受限制。

## 🔗 分享链接长什么样

**单文件分享的链接会带上原文件名后缀**，看起来就像一条正常的文件地址，也方便订阅类客户端识别：

```
https://<域名>/s/af198099-2597-41dc-91ba-ab2ff368bd98/光速雷达.yaml
                                         └── 口令 ──┘  └── 原文件名 ──┘
```

| 分享对象 | 生成的链接 | 对方打开后看到什么 |
| --- | --- | --- |
| **单个文件** | `/s/<口令>/<原文件名>` | **直接就是文件内容**。文本按纯文本显示，图片直接显示，PDF 用浏览器内置阅读器打开；**HTML 例外**——返回只读壳页面把正文渲染出来（页面自己的 CSS / 图片会加载，脚本禁用，见下节） |
| **整个目录** | `/s/<口令>` | 一个只读的浏览页面，可以进子目录、预览、下载 |

- **界面上显示的是可读形式**（`.../s/<口令>/菜鸟.txt`），不是 `%E8%8F%9C%E9%B8%9F.txt` 那种编码，
  跟浏览器地址栏看到的一致；**复制出去的也是可读版**，粘到浏览器/微信里都能正常打开。
  同时保留一个「复制编码版」，需要粘进命令行或老客户端时用（全 ASCII 更保险）
- 链接末尾的文件名只是「好看 + 便于识别」，改写或去掉都不影响访问（`/s/<口令>` 一样能用）
- 文件名里的**空格、`#`、`?` 等仍会保持转义**（`%20` `%23`），因为这几个字符不转义会把链接截断
- 单文件分享加 `?dl=1` 变成**强制下载**：`/s/<口令>/光速雷达.yaml?dl=1`
- 旧式的 `/sub/<口令>` 前缀也兼容，两种都能开
- 分享面板会同时给出**二维码**，手机扫码即可打开
- 两种链接都是**只读**的：对方改不了、删不了，也不能借机创建新分享
- **改名或移动**被分享的文件/目录时，链接会**自动跟随**，不会失效
- **删除**被分享的对象时，对应链接与记录会**自动清除**，不会残留在分享列表里
- 设置了有效期的链接，KV 到期自动删除，列表里也不会再出现

### HTML 单文档分享：像真页面一样渲染，但脚本不执行

分享出去的 `.html`（含 `.htm` / `.xhtml`）**不再是"一条链接看到源码"**——直接打开
`/s/<口令>/页面.html` 会得到一个只读壳页面，正文渲染在其中：

| 打开方式 | 看到什么 |
| --- | --- |
| 直接打开链接 | 壳页面：文件名 + 体积 + 修改时间 + 「渲染 / 源码 / 下载」 |
| 壳页面里的预览 | iframe（`sandbox` 无 `allow-scripts` / `allow-same-origin`）加载 `?doc=1`——**真文档**，与目录分享页里预览 HTML 同一套隔离思路 |
| `?doc=1` | 原文 + 一个注入的 `<base href="/s/<口令>/" target="_blank">`，带 `script-src 'none'` 的 CSP（壳页面的 iframe 用这个） |
| `?raw=1` | 纯文本原文（「源码」视图与脚本类客户端用；**点「源码」才请求**，打开页面不拉全文） |
| `?dl=1` | 强制下载（原字节 + `attachment`，行为不变） |

> **存成 `octet-stream` 的 `.html` 也能预览**：有些系统/浏览器上传时给不出 `file.type`，
> 文件会以 `application/octet-stream` 入库——以前预览链路只认"存储类型"，这类文件在管理端
> 和分享页都看不到渲染（iframe 拿到的是下载流）。现在三处预览关卡（管理端 `/f/…?doc=1`、
> 分享壳/真文档、分享目录真文档）**以后缀再认一次**：后缀是 `.html/.htm/.xhtml` 就按网页走，
> 照样进沙箱 + 照样带 `script-src 'none'`，安全姿势不变。同时上传时也会补类型：
> `file.type` 为空且后缀是 `.html` 就按 `text/html` 存，新文件不再踩这个坑。

**页面自己的资源能加载了**：因为走的是真实 URL + `<base>`，页面里 `style.css`、`img/logo.png`
这类**相对路径**会请求 `/s/<口令>/...`，由一条"分享内资源通道"提供。它只放行**被动类型**
（CSS / 图片 / 字体，**不含 JS 与 HTML**），路径必须落在被分享文件所在目录内（复用同一套
归一化，目录穿越不成立），类型也由白名单给出而不是照抄存储值。第三方外链（别的域名上的
文件所在目录内（复用同一套归一化，目录穿越不成立）。第三方外链（别的域名上的
CSS / 图片 / JS）一律不加载 —— CSP 的 `img-src` / `style-src` 只放行 `'self'` 与 `data:`。
这些资源与壳页面一样**走边缘缓存**：重复访问命中缓存时 **0 次 R2 读**（代价是改了图 / 样式
重新发布后最多 60 秒生效 —— 资源 URL 不可枚举，清缓存清不到它们）。

**为什么不能直接返回 `text/html`**：那等于让上传者的页面脚本跑在你的域名下——脚本发的请求会
自动带上会话 Cookie，登录过的管理员打开恶意分享链接，对方就能以管理员身份读文件、删文件、建分享。
HttpOnly 只防"读"Cookie，不防"用"Cookie。所以三道闸：**iframe sandbox**（不给脚本与同源权限）、
**响应头 CSP**（`script-src 'none'`，文档改不掉）、**资源通道白名单**（脚本文件取都取不到）。
结果是：脚本永远不执行、读不到主站 Cookie/存储、发不出请求。

**页面里的链接默认开新标签**：注入的 `<base>` 带了 `target="_blank"`。这不是锦上添花——
沙箱 iframe 里点一个**不带 target 的外链**时，帧会自身开始导航，被壳页面 CSP 的
`frame-src 'self'` 拦下，Chrome 随即把整个正文帧换成 `chrome-error://` 的错误页，**存档当场废掉**
（要刷新才回得来）。论坛类页面（Discourse 等）正文链接绝大多数都不带 `target`，命中率极高。
带上 `target="_blank"` 后走 sandbox 的 `allow-popups`，新标签直接打开原站，**存档页安然不动**。
已知取舍：页内 `#锚点` 也会跟着开新标签（静态存档里这类多是回复/分享按钮，本来就没意义）。

> 注意：链接**指向的内容**不会跟着存档 —— 点开仍去原站（可能需要登录）。

还有几个边界：超过 **4MB** 不建壳页面，直接退回纯文本源码；`<base>` 是**字节级**插到
`<head>`（没有 head 就插在 doctype 之后）——不解码整篇，所以 GBK / Big5 页面照样按原编码发出；
UTF-16 文档跳过注入（相对资源不解析，页面照样能看）。页面之间**互相跳转的 HTML 链接**也不加载
（白名单里没有 html），需要整站效果请用「下载」。

> SVG 同理但更严：独立 SVG 文档里脚本也能执行，所以 SVG **直链**按纯文本返回（`?dl=1` 下载保留
> 原类型）；作为页面资源（`<img src="x.svg">`）时按 `image/svg+xml` 提供，并单独钉一份最严 CSP。

### 📋 关于复制

- **手机上也能复制**：复制优先走「点击手势内同步 `execCommand`」，不依赖 Clipboard API
  （后者在异步回调里必然被浏览器以"缺少用户激活"拒绝，这正是之前手机端复制失败的原因）
- 万一两条路都不通（少数浏览器/WebView），会弹出**手动复制面板**：链接自动全选，
  长按 → 拷贝即可；有 `navigator.share` 的话还会给一个**系统分享**按钮
- 链接框点一下就复制；生成链接后的自动复制是**静默**的，失败不会弹"复制失败"打扰你

## 👀 对方看到的分享页长什么样

分享页是一个**纯浏览**的界面，和你的管理界面完全是两套东西 —— 管理端的东西一个都不会出现。

> 访客看到的**永远是你最后一次点「发布」时的版本**。你在管理端怎么改、什么时候改的，
> 都不会自动流到分享页 —— 要让访客看到新内容，得点一次「发布」。见「编辑与分享分离」一节。

**目录分享**：左边是分享内容本身的目录树（标题就是分享的目录名，不叫「根目录」），
点文件在右边看，右上角只有「下载 / 返回列表」。

**打开一个文本文件**：是一个**只读查看器**，不是编辑器：

| 会看到 | 不会看到 |
| --- | --- |
| `只读分享` 徽标、`只读查看` 标记 | ❌ 保存按钮 |
| 文件名 + 体积 + 修改时间 | ❌ 字号调节 A- / A+ |
| 「渲染 / 源码」切换（`.md` / `.json` / `.csv` / 代码） | ❌ 分享设置面板 |
| 「复制全文」+「下载」「返回列表」 | ❌ 上传 / 新建 / 批量操作 / 勾选框 |
| 图片 / 音视频 / PDF 灯箱 | ❌ 查找替换、行号槽、大纲 |
| `N 行 · M 字符` 统计 | ❌ 任何可以输入的地方 |

**渲染能力对访客是完整的**：Markdown 会**渲染成网页并自动带目录**（点目录能跳转），
CSV 能点表头排序，代码会语法高亮，图片能开灯箱缩放旋转。
「源码」按钮随时切回原始文本，两边看都行。

那些管理端的东西**不是用 CSS 藏起来的，而是服务端根本不输出这些 DOM** ——
访客页的 HTML 里连 `#edt`、`#findBar`、`#edGutter` 这些 id 都不存在。这样改样式也露不出来。

内容用只读文本块呈现（不是输入框），**点进去不能打字、不会弹出手机键盘、也没有光标闪烁**，
一眼就知道是"看"而不是"改"；文字照样可以选中、复制。

服务端对访客的写操作一律返回 **403** —— 界面藏起来只是不误导人，真正的防线在服务端。

## 📦 部署前准备

需要两个 Cloudflare 资源：

| 资源 | 用途 | 绑定变量名（必须一致） |
| --- | --- | --- |
| **R2 存储桶** | 存放文件夹与文件本体 | `R2` |
| **KV 命名空间** | 存放分享口令 / 登录态（可选，不用分享可不绑） | `KV` |

> ⚠️ **R2 需要先绑定支付方式才能开通**，这是 Cloudflare 的硬性要求，免费额度内不会扣费。
> 路径：右上角头像 → **Billing → Add Payment Method**，绑卡后回到
> **R2 Object Storage → Enable R2** 即可。
> R2 免费额度（每月）：10GB 存储、100 万次写操作、1000 万次读操作，**出口流量永久免费**。
> 不够用也没关系，超出部分才按量计费。

## 🚀 一键 Workers 部署（建议有域名的部署）

1. **先开 R2**：头像 → Billing → Add Payment Method 绑卡，再到 **R2 Object Storage → Enable R2**
2. 在 **R2** 里新建一个存储桶（例如 `my-drive`），名称只能小写字母 + 数字 + 连字符
3. 在 **Workers & Pages → KV** 里新建一个 KV 命名空间（可选，需要使用「分享」功能时必须）
4. 在 **Workers & Pages** 里新建一个 **Worker**（选 Hello World 模板即可），进入在线代码编辑器
5. 把编辑器里的默认代码**全部删掉**，粘贴本项目 `worker.js` 的全部内容，点 **部署**
6. 回到这个 Worker 的 **设置 → 绑定（Bindings）**，添加两条：
   - `R2 存储桶`，变量名填 **`R2`**，选择第 2 步建的桶
   - `KV 命名空间`，变量名填 **`KV`**，选择第 3 步建的空间
7. 在 **设置 → 变量（Variables）** 中添加 `ADMIN_UUID`，值随便填一串别人猜不到的字符
8. 保存后**再部署一次**（绑定改动必须重新部署才生效）
9. 访问 `https://<worker名>.<你的账户>.workers.dev/<ADMIN_UUID>`，能打开页面就成了
10. 想用自己的域名：在该 Worker 的 **设置 → 域和路由（Domains & Routes）** 里添加自定义域名

## 🚀 一键 Pages 部署（适合没有自定义域名的部署）

1. 先按上面第 1、2 步开通 R2 并建好存储桶；需要分享的话再建一个 KV 命名空间
2. 在 **Workers & Pages** 里新建一个 **Pages** 项目，选择「直接上传 / Upload assets」
3. 上传 `pages.zip` 压缩包，保存并部署
4. 在 Pages 项目 **设置 → 绑定** 中添加 `R2`（必填）与 `KV`（可选），变量名必须一字不差
5. 在 **设置 → 变量** 中添加 `ADMIN_UUID`
6. **重新上传 `pages.zip` 并再次部署（很重要！这一步是为了让绑定生效）**
7. 访问 `https://<pages域名>/<ADMIN_UUID>` 进入管理页

## ⚙️ 环境变量

| 参数名 | 必填 | 说明与示例 |
| --- | --- | --- |
| **ADMIN_UUID** | ✅ | 管理页入口路径，任意字符串 / UUID 均可。<br>例：`8c3b9f3a-9f4b-4c2e-b8a1-3a4f6e8c9f8a`，则访问 `/8c3b9f3a-...` |
| **R2** | ✅ | R2 存储桶绑定，变量名必须填 **R2**（存放文件夹与文件）。 |
| **KV** | ❌ | KV 命名空间绑定，变量名必须填 **KV**。**分享链接功能依赖它**，不绑则「分享」按钮不可用，其余功能正常。 |
| **FILENAME** | ❌ | 管理页标题，默认为 `CF-Workers-TXT`，可按需修改。 |
| **PASSWORD** | ❌ | 设置后管理页需要登录，右上角会出现「退出」按钮。**强烈建议设置。** |
| **SESSION_DAYS** | ❌ | 登录态保持天数，默认 `30`。设 `0` 表示关闭浏览器即退出（更安全）。上限 365。 |
| **RATE_LIMIT** | ❌ | 每 IP 每分钟请求上限，默认 `240`，超出返回 429。设 `0` 关闭（不建议）。 |
| **DOWNLOAD_LIMIT** | ❌ | 每 IP 每分钟分享文件直连次数上限，默认 `60`。防止单个 IP 刷你的分享内容。设 `0` 关闭。 |
| **INDEX_TEXT_CAP** | ❌ | 全文搜索索引里保存的正文总量上限（字节），默认 `1048576`（1MB）。<br>调大能搜到更多正文，但免费版 Worker 单次只有 10ms CPU，**不建议超过 2MB**；升级到付费版（30s CPU）可以放宽。<br>**硬上限 1.5MB（1572864）**：填再大也会被夹回这个值，避免搜索请求因 `JSON.parse` 超 CPU 直接报 1102。 |

> `ADMIN_UUID` 就是管理入口，请当成密码看待，不要外传。

## 📏 上限瓶颈：能传多少、撞到之后会怎样

下面每一行都是**实测出来的**（不是推测），撞到上限时的行为也写清楚了。

### 上传单个文件

| 情况 | 上限 | 撞到之后 |
| --- | --- | --- |
| **走普通 PUT**（≤ 8MB） | **100MB** | 超过则 Cloudflare 直接返回 **413**，前端提示「文件过大，超出服务端请求限制」 |
| **走分片上传**（> 8MB） | **4.995 TiB** | R2 侧硬上限；单片固定 8MB，10000 片用尽才是天花板，**实际上不会撞到** |
| 分片阈值 | 8MB | 小于它走单次 PUT（更省 Class A 操作）；大于它自动分片，可断点续传 |

> 也就是说**单文件真正的瓶颈是 100MB**（免费版/Pro/Business 的请求体上限），
> 分片机制只是为了绕过这一条。R2 本身支持 5TiB 单对象、分片最多 10000 片、单片 5MiB~5GiB。
> 详见 [Workers 限制](https://developers.cloudflare.com/workers/platform/limits/) 与 [R2 限制](https://developers.cloudflare.com/r2/platform/limits/)。

### 一次上传多个文件

| 操作 | 上限 | 撞到之后 |
| --- | --- | --- |
| **多选文件上传**（`handleFiles`） | **不限个数**（只是串行上传，慢） | 无硬上限，进度面板逐个显示 |
| **文件夹上传**（`uploadTree`） | **不限个数**，4 路并发 | 同上；单个失败不中断整批，最后汇总「完成 N/M（失败 K）」 |
| **批量删除 / 批量移动** | **200 个/次** | 超出部分**静默丢弃**，`count` 字段如实回报实际处理的 200 |

> 批量操作的 200 是**每次请求**的上限。前端选 500 个文件批量删，会删掉前 200 个 → 需要分批操作。

### 全文搜索

| 项目 | 上限 | 撞到之后 |
| --- | --- | --- |
| **索引正文的文件数** | **3000 个** | 超出部分降级为「只按文件名搜」：搜文件名一定能搜到，**搜正文搜不到** |
| **索引正文总量** | **1MB**（`INDEX_TEXT_CAP`） | **渐进降级**：单文件片段从 8KB 逐步缩短到 512B，仍放不下的才只按文件名；片段长度是连续变化的（实测 23 种） |
| **单个文件索引正文的大小** | **512KB** | 超过不索引正文，文件本身照常保存，搜文件名能找到 |
| **搜索补扫 R2 对象数** | **5000 个** | 第 5001 个之后的文件按文件名搜不到（但如果已进索引，正文照搜得到） |
| **单次返回结果数** | **1 ~ 200**（缺省 60） | 超出走分页（`hasMore` / `total`） |
| **参与评分的结果数** | 5000 | 超出部分不参与排序 |
| 索引满载时搜索耗时 | — | 索引总体积约 **1.1MB**，单次搜索约 **10ms**，**正好贴着免费版 10ms CPU 红线** |

> ⚠️ **这是最需要注意的一条**：索引到 1MB 后单次搜索就会逼近免费版的 CPU 上限，再多内容就可能被 Cloudflare 打成 1102 错误。
> 三个调节手段，优先级从高到低：① 点「重建 / 更新正文索引」把不常搜的文件清出索引；
> ② 升级付费版（CPU 30 秒）；③ 谨慎调大 `INDEX_TEXT_CAP`（硬上限 1.5MB）。

## 📁 文件存在哪里

全部数据都在你的 R2 桶里，规则很简单：

```
d/<文件夹路径>/          ← 零字节占位对象，代表「空文件夹」
d/<文件夹路径>/<文件名>   ← 真实文件（草稿树，管理端读写）

__pub__/<路径>/          ← 已发布副本（影子树，只有分享页读）
```

`d/` 是**草稿树**，`__pub__/` 是**已发布影子树** —— 两者物理隔离，改草稿不会影响分享页，
只有点「发布」才会把内容复制过去（见「编辑与分享分离」一节）。
`__pub__/` 里没有你直接改的东西，删掉它等于把所有分享退回"待发布"，
在分享管理里点一次「全部发布」就能全部恢复。

想迁移或者清空，直接在 R2 控制台操作即可。

KV 里存的是这些（前缀区分，互不干扰）：

| Key | 内容 | 删除的后果 |
| --- | --- | --- |
| `share:<口令>` | 分享记录（路径 / 类型 / 有效期） | 分享链接全部失效 |
| `idx:v1` | **全文搜索索引**（各文件前 8KB 正文 + 元数据） | 搜索退化成"只按文件名"，重新建索引即可恢复 |
| `mp:<uploadId>` | 未完成的分片上传会话（24 小时过期） | 大文件需要重新开始上传 |
| `loginfail:<IP>` | 登录失败计数（10 分钟过期） | 锁定被重置（只影响防爆破） |

> 全文搜索索引已迁到 R2（`__sys__/idx.json`，不在你的文件目录里、不会被列出或删除），
> **不再占用 KV 的读/写配额**。旧版本存在 KV 的 `idx:v1` 会在升级后首次访问时自动迁移并清理。

> 删掉 `idx:v1` 没有任何数据损失 —— 文件本体在 R2，索引只是加速层，随时能重建。

## ⚠️ 注意事项

- **单文件大小**受 Cloudflare 请求体上限约束（免费版约 100MB），特别大的文件建议先压缩。
- 删除文件夹会**递归删除**里面所有内容（连目录占位一起清掉，不会留下空壳文件夹）；批量操作一次最多处理 200 项，操作不可撤销。
- 单个文件夹内的文件超过 **500** 个时，移动/重命名会被拒绝（R2 没有服务端复制，只能逐个搬运），请分批处理。
- **上传文件夹是逐文件上传**（4 路并发）、**多选上传是 3 路并发**（撞到限速会自动退避重试），
  几百个文件会花上几十秒到几分钟，属正常；单个文件仍受 100MB 请求体上限约束。
- 分享口令**就是访问凭证**，谁拿到都能看。不想再分享时，在「分享」面板里点「取消」即可立即失效。
  只想**暂时**收起来（比如内容在改），点「撤回」就行 —— 草稿和链接都留着，改好了点「发布」发回去。
- **从旧版本升级到这一版，历史分享需要补发一次**：老版本没有影子树，链接记录还在但内容没复制过去，
  打开「分享管理」点 **「全部发布」** 即可（已发布的会自动跳过，不会覆盖新版本）。
- 分享只读、不可写入；**拿到口令的人可以反复访问**，默认每 IP 每分钟 60 次，想更严就配 Cloudflare 的 Rate Limiting 规则。
- 分享记录存在 KV 里，所以**分享功能依赖 `KV` 绑定**；不绑 KV 时其余功能（含左侧目录树）都正常。
- 绑定变量名 `R2` / `KV` **不能改名**，代码里读的就是这两个名字。
- **`PASSWORD` 记得设。** 只靠 `ADMIN_UUID` 保护时，链接被谁看到就等于把钥匙给了谁。
- 共用电脑上用完点右上角「退出」；或者把 `SESSION_DAYS` 设成 `0`，关浏览器就下线。
- 觉得登录态可能泄露了，直接**改 `PASSWORD`** —— 所有旧登录态会立刻失效。
- **全文搜索需要 `KV` 绑定**。索引是**保存时同步写**的：上传 / 保存文件时当场把这个文件写进索引，
  所以**改完第一次搜索就能搜到新内容**，不存在"要再搜一次"的窗口。
  唯一需要手动处理的是**从控制台 / S3 / rclone 直接放进 R2 的文件**（保存接口碰不到它们）——
  这类文件**仍能按文件名/路径搜到**（搜索会补扫 R2），但**正文搜不到**，
  点一次「重建 / 更新正文索引」即可补上。
- 索引只保留每个文件的**前 8KB 正文**。超过 8KB 的文件在结果里会标「可能截断」，
  点「深搜此文件」可以读全文做精确验证。这是为了控住索引体积与 Worker 的 CPU 配额。
- **媒体预览需要浏览器支持**：图片 / 音视频 / PDF 都是浏览器原生能力，格式太冷门（如 `mkv` 的某些编码）可能播不了，
  这时用「下载」用本地播放器打开。
- **分片上传只在超过 8MB 时启用**（R2 的多段上传按 Class A 计费，小文件走多段反而贵）。
  上传大文件中途断了或关了页面都不要紧：**重新选择同一个文件**，已传好的分片会被自动跳过、接着往下传。
  （浏览器不允许网页在刷新后自己读取本地文件，所以"重新选一次"这一步省不掉；但已传的部分不会白费。）
  页面加载时如果检测到没传完的会话，会主动提示你。
- 编辑区的**行号槽**在内容超过 512KB 或超过 4000 行时会自动关闭，这是为了不让输入变卡；
  内容本身完全不受影响。
