## 代码结构分析（重要基线）
- `pages.zip` 里的 `_worker.js` 与 `worker.js` **代码完全一致**，仅多/少 3 行头部注释。
- 全站只有 3 个路由：
  - `GET /{ADMIN_UUID}` → 返回带单个 `<textarea>` 的管理页
  - `POST /{ADMIN_UUID}` → body 整体写入 KV；若 body 以 `GUESTGEN|` 开头则写 `GUEST_TOKEN`
  - `GET /sub?token=xxx` → 校验 token 后以 `text/plain` 返回 `TEXT.txt`
- KV 只使用 2 个固定 key：`TEXT.txt`（全站唯一一份文本，覆盖写）、`GUEST_TOKEN`（访客分享口令）。

- 项目**不支持**文件上传、文件夹上传、多文件/目录管理。前端无 `<input type="file">`，后端不解析 `multipart/form-data`，KV 中无索引/路径概念 → 本质是"单个共享记事本"。

## 第二轮：补上「单文件直连分享」+「批量删除」

用户反馈两个硬伤：
1. 只能分享目录，`/s/<token>` 永远是浏览页 → 拿不到「一条链接直接看正文」的效果（原项目 `/sub?token=` 就是直连文本的）
2. 不能批量删除

### 实现（worker.js 现 1363 行 / 54845B）
- 分享记录改成 `{path, kind:'file'|'dir', at}`，`kind` **由服务端自动判定**：
  `bucket.head(ROOT + path + '/')` 存在 → 目录，否则 → 文件。
- `GET /s/<token>` 按 kind 分流：
  - file → `serveSharedFile()` 直接吐原始字节，文本类统一 `text/plain;charset=utf-8` 内联（不弹下载）；
    图片/PDF 保留原 Content-Type + `inline`；加 `?dl=1` 强制 attachment。
  - dir → 仍是只读浏览页 + `/s/<token>/api`
- 新增 API：`shares`（列出全部分享）、`unshareAll`、`deleteBatch`（`{items:[{path,isDir}]}`，上限 200）。
- 前端：每行加勾选框（`state.sel`），底部浮动批量条（已选 N 项 / 全选本页 / 取消选择 / 批量删除）；
  每行加「分享」按钮；分享弹窗改成**分享管理面板**（生成 + 列表 + 打开/复制/取消）。
- `#batch` 的 z-index 必须**低于**弹窗遮罩（用 40，遮罩 50），否则确认框会被批量条压住。

### 本轮修的真实问题
- `deletePath` 删不存在的文件也返回 1，导致 `removed` 计数虚高 → 改成先 `head()` 再删。
- `mkdir` 只查了目录占位，没查同名文件 → 会出现 `d/x` 和 `d/x/` 同时存在（列表里一个文件一个文件夹同名），
  且分享时 kind 判定会歧义。已加同名文件检查。

### 验证
集成测试扩到 **40 项断言全过**（含单文件直连正文/图片 inline/`?dl=1`/目录只读/分享管理/批量删除/删除后链接失效/安全回归）；
前端静态检查通过；无头 Chrome CDP 在 1280/390/360 三视口做逐元素溢出检测 + 真实 DOM 断言

## 第三轮：移动 / 有效期 / 删除清理分享 / 左侧目录树

用户提出 4 个缺口，全部实现（worker.js 现 74152B）。

### 1. 移动文件与文件夹
- 新增 `move` action：`{path, isDir, toDir, newName}`，可同时改名。
- 抽出 `moveObjects(bucket, srcPrefix, dstPrefix)` 复用给 `rename`（rename 现是 move 的特例）。
- 校验：目标目录必须存在、不能移进自己内部（`toDir === p || toDir.startsWith(p + '/')`）、
  目标同名文件/文件夹 409、上限 500 对象。
- 新增 `moveBatch` action（`{items, toDir}`），同名冲突跳过并计入 `failed` 而不是整体失败。
- 前端：**「重命名」按钮已被「移动」取代** —— 同一个弹窗左边改名、下面浏览目标目录，
  弹窗里用 `ensureKids` 复用目录树数据。批量条加了「批量移动」。

### 2. 分享有效期
- `share` action 加 `expiresIn`（秒，0=永久，<60 归一到 60，上限 1 年）→ KV `expirationTtl`。
- 记录里存 `exp`（ms）用于展示剩余时间；KV 到期自动删除 key，列表自然不含。
- 前端下拉：1 小时 / 1 天（默认）/ 7 天 / 30 天 / 永久；列表用 amber 标签显示「剩余 N 天/小时/分钟」。

### 3. 删除后自动清理分享
- `purgeShares(kv, path)`：删掉 `path` 本身及 `path + '/'` 下的全部分享记录。
  在 `DELETE`（单个）与 `deleteBatch` 里都调用，返回值里带 `shares` 数量。
- `shares` 列表加了**自愈**：逐个 `head` 校验目标是否还在（前 200 条），
  不在的删除底层记录并计入 `cleaned`。防住历史残留。
- `retargetShares(kv, oldPath, newPath)`：移动/重命名后**把分享指向新路径**，链接不会失效。
  剩余 TTL 会按 `exp` 重算，不足 60 秒的直接清掉。

### 4. 左侧目录树导航
- 新增 `GET api?action=tree&path=` → 只返回该层子文件夹 + 文件名（懒加载，不拉全量）。
- 前端 `tree = {open:{}, kids:{}}`，`ensureKids()` 缓存、`expandTo(path)` 沿祖先链串行加载并展开。
- 当前目录 `.trow.cur` 高亮；桌面 sticky 侧栏 236px；≤900px 变抽屉（`body.side-open` + 遮罩 + 汉堡按钮）。
- 结构变更（mkdir/move/delete/批量）后调 `invalidateTree()` 清缓存。

### 本轮关键坑
- **弹窗 `onOk` 契约**：原来只看同步返回值，异步失败也会关弹窗。
  改成支持 Promise —— 只有 resolve 值不是 `false` 才关闭，失败时弹窗留着让用户改。
- **`--window-size` 截图在手机上不可信**：Chrome 会把布局宽度钳到 ≥500，
  但截图仍只有请求的宽度 → 图是**被裁过的**，看起来像溢出。手机截图必须走 CDP
  `Emulation.setDeviceMetricsOverride` + `Page.captureScreenshot`。
- **溢出检测要排除有意移出屏幕的元素**：手机端抽屉侧栏 `left:-272px` 是设计如此，
  逐元素检测会全部误报。判据：`position:fixed` 且有 `translateX(-100%)` 的祖先。

### 验证
集成测试 **55 项全过**（目录树、移动文件/文件夹、自身移动拒绝、同名冲突、批量移动、
有效期过期失效、删除清理分享、外部残留自愈、访客权限、路径穿越）；
前端静态检查通过；无头 Chrome CDP 在 1280/390/360 三视口跑 **12 个场景**，

## 第四轮：退出登录 + 会话时长 + 登录限速

用户反馈「没有退出登录按钮，安全性不到位」。

### 实现
- **退出登录**：`GET/POST {ADMIN_UUID}?action=logout` → 302 + `Set-Cookie: wbauth=...; Max-Age=0`
  回到管理页（落到登录页）。处理放在**鉴权之前**，未登录时点也无害。
- **只在设置了 `PASSWORD` 时才渲染「退出」按钮**（`HAS_PW` 注入到前端）。
  没设 PASSWORD 就没有会话，退出无意义 —— 真正的风险是「URL 即密码」。
- **`SESSION_DAYS`** 新环境变量：登录态保持天数，默认 30，`0` = 关闭浏览器即退出，上限 365。
  非法值回落默认。`0` 时不下发 `Max-Age`（会话 Cookie）。
- **登录失败限速**：按 `CF-Connecting-IP` 计数存 KV `loginfail:<ip>`，10 分钟内错 8 次 → 429，
  期间即使密码正确也拒绝。登录成功清零。KV 最终一致，属尽力而为；未绑 KV 时自动跳过。
- 退出/登录响应都加了 `Cache-Control: no-store`。

### 本轮修的真实问题
- 退出时的 `Set-Cookie` 拼出**双分号** `wbauth=;; Path=/...`：
  因为 `cookieAttrs` 本身以 `; ` 开头，前面又写了一个 `;`。已修正，并把 `!includes(';;')` 写进断言。

### 验证
后端 **44 项全过**（HAS_PW 注入、退出清 Cookie 且属性完整、SESSION_DAYS 0/7/9999/非法值、
限速 8 次后 429、换 IP 不受影响、锁定期内正确密码也拒、10 分钟后解锁、成功登录清零、
无 KV 时跳过限速、改密码后旧 Cookie 立即 401、分享页不受登录态影响）；
前端静态检查通过；无头浏览器 **7 个场景**通过，含**端到端**「点退出 → 确认 → 落到登录页」。
