## CF-Workers-TXT 分享页 HTML 渲染行为分析

用户提问：部署在 Cloudflare 上后，分享的 HTML 文件是否无法渲染。结论（读 worker.js 验证）：

- **单文件分享直链**（`/s/<口令>/x.html`）：`buildSharedFile()`（worker.js:767-808）命中 `TEXTY` 正则（worker.js:699），强制把 Content-Type 改写为 `text/plain;charset=utf-8`，浏览器只显示源码、不渲染网页。这是**刻意的防 XSS 设计**（代码注释 776 行明示）。
- **目录分享只读页**（`/s/<口令>`）：前端 `kindOf()`（worker.js:5375-5399）把 .html 分派到 html 渲染器，用 `<iframe sandbox="allow-popups allow-popups-to-escape-sandbox" referrerpolicy="no-referrer" srcdoc=...>`（worker.js:6010）渲染：外观可显示，但无 allow-scripts / allow-same-origin，脚本不执行、跨源隔离，srcdoc 的 base URL 是 about:srcdoc 所以相对路径外链资源加载不了；可切「源码」。
- 顺带发现：SVG（image/svg+xml）不在 TEXTY 内，单文件直链会保持原类型内联返回，独立 SVG 文档中脚本可执行——若在意可在 buildSharedFile 里一并纳入强制纯文本。

## 实施：HTML 分享「真文档模式」——页面自己的 CSS/图片能加载了

用户采纳优化建议①。机制从"srcdoc 注入"改为"真实 URL 文档 + base 注入"：

- **`?doc=1`（新增出口）**：`sharedHtmlDoc()` 返回原文 + 注入 `<base href="/s/<口令>/">`，带响应头 CSP。**字节级注入**（`injectBaseTag`/`asciiIndexOf`，只在前 8KB 找 `<head>`→`<!doctype>`→`<html>` 锚点），不解码整篇——省免费版 10ms CPU，也不动原文编码声明（GBK/Big5 原样发出；UTF-16 跳过注入）。编码用 `sniffEncoding` 决定响应 charset。
- **壳页面**：iframe 改 `src = ?doc=1`（真实 URL 才解析得对相对路径），**删掉 iframe 的 csp 属性**（它会连自己目录的图片一起挡掉），改由文档响应头 CSP 管；**源码改为按需 fetch**（打开页面只打一个请求，旧版是壳+原文两个）；`<base>` 只加在渲染文档上，`?raw=1` 仍是干净原文。
- **分享内资源通道**：路由里 file+HTML 分享才有；`SHARE_ASSET_MIME` 白名单只放行 css/图片/字体（**无 js/html**）；路径按"被分享文件所在目录"用 `safeDir(normPath(...))` 归一化（穿越不成立）；类型由白名单给出；svg 资源单独钉最严 CSP；单段非白名单后缀仍走旧的"后缀不参与查找"兜底，深层非白名单直接 404；资源**不吃 DOWNLOAD_LIMIT**（一个页面几十个资源正常）。
- **`applySecurity`**：响应自带 CSP `frame-ancestors` 时不再强行 `X-Frame-Options: DENY`（否则自己的壳页面也嵌不了）。这是零成本改动，注意这条。
- **purgeShareCache**：清 `?doc=1/?raw=1/?dl=1` 两种 URL 形式；页面内静态资源不清（不可枚举，靠 max-age=60 过期）。
- 安全不变：sandbox（不给脚本/同源）+ 文档响应头 CSP `script-src 'none'` + 资源白名单，三道闸。浏览器日志确认脚本仍被拦。
- 测试：htmlshell.mjs 扩到 53 项（含穿越与泄露断言），htmlshell_browser.mjs 重写为 31 项（新增 Network 域断言：`?doc=1` 200、`outer.css` **200 加载成功**、第三方图片仍被挡、打开时不请求 `?raw=1`）；check.mjs 断言随机制更新（sandbox 断言要**精确取属性值**——脚本注释里出现 `allow-scripts` 字样会误报）。截图 `shots/html-share-shell.png` 背景变红 = outer.css 生效。
- pages.zip 已重建。

## 线上事故定位与修复：分享链接「第一次能开、60 秒内再开就 500」

用户给了线上链接（note.istudy.qzz.io，.htm 文件分享）。现象：`error code: 1101`。
定位过程（值得复用的套路）：
1. 同域其他路径正常（/manifest /icon /404）→ 整个 Worker 没挂，只有分享路径挂；
2. 对照不同 URL 形状：能提前 404 返回的路径（`/a/b.css`、坏 token）**从不失败**，
   凡走到 `serveSharedFile` 的都随机失败 → 范围锁到"壳 + 边缘缓存"这条路；
3. 12 次采样：第 1 次 200、之后全 500 → **有状态**；
4. `sleep 70` 让 `max-age=60` 的缓存条目过期 → 第 1 次 200、紧接着第 2/3 次 500 → **命中缓存即抛**。

根因：`caches.default.match()` 返回的 Response **头部不可变**，而最外层 `applySecurity()`
直接在它上面 `res.headers.set(...)` → 抛 "Can't modify immutable headers" → 1101。
**这是改动前就存在的 bug**（applySecurity + serveSharedFile 缓存都是老代码），
影响所有分享直连（不只 HTML）：任何链接在缓存 TTL 内被第二次打开就 500。

修复：`applySecurity` 改成 `const h = new Headers(res.headers)` 后 `new Response(res.body, { status, statusText, headers: h })`，
套一层流不缓冲，成本可忽略。已 grep 确认没有别处直接改响应头。

测试缺口与补齐：Node 里**没有全局 `caches`**，所以此前所有测试都没走过缓存分支 —— 这正是 bug 藏住的原因。
- `mock.mjs` 新增 `makeCaches()`，**复现"缓存命中返回的 Response 头部不可变"**（defineProperty + 会抛的 set/append/delete）；
- 新增 `sharecache.mjs`（33 项）：同一 URL 连打两次断言都是 200、内容一致、安全头仍在（壳/?doc=1/?raw=1/?dl=1/txt/资源）。
- check.mjs 加守卫：applySecurity 必须复制头部再改，禁止 `const h = res.headers;`。

回归：check ✅ / sharecache 33 ✅ / htmlshell 53 ✅ / backend 242 ✅ / 两个浏览器套件 31+19 ✅。pages.zip 已重建。
（顺带记录：资源通道**不走 Worker 缓存**，只靠 `Cache-Control: public, max-age=60`；CDN 是否缓存 Worker 响应不确定，所以资源每次都读 R2 —— 想省可以在 serveShareAsset 里也挂 cache.put。）

## 存档页里的链接：点一下会把正文帧顶成错误页（已修）

**现象**：用户反馈"用插件存的 HTML，页面里的链接保存不下来"。实测他给的那条 linux.do 分享
（SingleFile 抓的 Discourse 主题页，1.87MB）：链接其实**都在**——203 个 `href`，其中 85 条是
真链接（124 条是 `#` 界面按钮），图片 31/31 已被 SingleFile 内联成 `data:`。真正的问题在**点击**。

**根因**（无头 Chrome + 真实鼠标事件实测，程序化 `.click()` 没有用户激活、结论不可信）：
沙箱 iframe 里点一个**不带 `target` 的外链**，帧会自身开始导航 → 被**壳页面 CSP 的
`frame-src 'self'`** 拦下 → Chrome 把整个正文帧换成 `chrome-error://chromewebdata/`，
存档当场废掉，要刷新才回得来。带 `target="_blank"` 的链接反而正常（走 sandbox 的 allow-popups）。
而 Discourse 这类论坛的正文链接**绝大多数不带 target**（该存档 85 条里 70 条），命中率极高。

**修复**：`sharedHtmlDoc()` 注入的 `<base>` 加 `target="_blank"`
（`<base href="..." target="_blank">`）——纯 HTML，不需要脚本（iframe 无 `allow-scripts`，注入脚本
那条路根本走不通）。`<base target>` 是文档的默认链接目标，所有不带 target 的链接于是走弹窗通道。
已知取舍：页内 `#锚点` 也会开新标签（静态存档里这类多是回复/分享按钮，本就没意义）。

**顺带验证一个隐患**：SingleFile 抓的页面**常常没有 `<head>` 标签**（他这份就没有），
`injectBaseTag` 的锚点于是回退到 `<!doctype>` 之后 —— 注入点在 `<html>` 之前，属"非法位置"。
实测浏览器会把 `<base>` 挪进 head，`document.baseURI` 正确指向分享目录、相对链接解析正确、
target 也生效。**结论：这个回退分支是可靠的，不用改**。

**新增测试**：`linkclick_browser.mjs`（17 项，需另起一台本地服务当"外站"，用
`Input.dispatchMouseEvent` 真实点击；断言正文帧纹丝不动 + 确实开新标签 + 无 `frame-src` 拦截日志
+ 无 `<head>` 文档的 base 仍生效）。serve.mjs 夹具新增 `笔记/链接.html`、`笔记/无head.html`。
check.mjs 加 2 条守卫（base 必须带 `target="_blank"`；sandbox 必须含 `allow-popups`）。
全量 9 套：check ✅ / htmlshell 53 ✅ / sharecache 36 ✅ / collect 46 ✅ / backend 242 ✅ /
htmlshell_browser 31 ✅ / linkclick 17 ✅ / pubbtn 19 ✅ / collect_browser 23 ✅。pages.zip 已重建。

**待办（用户尚未拍板）**：链接**指向的内容**仍不存档（点开去原站，可能要登录）。用户的诉求是
"论坛里的下载链接也想存下来"。设计草案：给采集管线加"跟进附件链接"——只对**看起来像资源的直链**
（`.zip/.pdf/.txt`、`?dl=1`、`/uploads/...`）当资源抓进 `assets/` 并把 `href` 改写成相对路径；
站内帖子链接可选"抓一跳"；网盘链接（百度/夸克等需登录、防盗链）无法自动存档，只能保留原链接
并生成"链接清单"。关键约束：**只抓"被动文件"，永不抓 HTML 页面**（那会引入一串页面级资源依赖）。

## 成本预算：新增 `cost.mjs`（回答"会不会把 Cloudflare 资源吃掉"）

用 mock 逐项计数（Worker 请求 / 出网 fetch / R2 Class A·B / KV 读写），跑一次就出数字，
并把它们**钉成断言**（谁把成本改爆会立刻红）。实测结论：

- 采集「中页面」（1 样式 + 20 图 + 5 附件）= **33 个 Worker 请求 · 32 次 R2 写 · 2 次 R2 读 · 0 次 KV 写**；
  请求数 ≈ 资源数 + 6（页面本身、3 次目录占位、附件清单、跳转）→ **线性、可预测**。
- **单次请求最多出网 1 次**（一资源一请求），所以永远不会撞免费版 50 子请求 / 10ms CPU 红线。
- **采集完全不写 KV**：限流 `rateTake` 用的是进程内 Map（不是 KV）—— 这点很关键，
  免费版 KV 只有 1000 写/天。KV 只在分享记录、分片会话、登录失败计数、分享改名时写。
- 换算免费额度：约 3000 次采集/天（Workers 10 万请求）、约 3 万次采集/月（R2 100 万 Class A，真正的瓶颈）。
- 访客访问分享页：首访每资源 1 请求 + 1 次 R2 读；**60 秒内再访问 0 次 R2 读**。

**顺手逮到并修掉一个真不一致**：目录分享的 `?doc=1` 原来直接调 `sharedHtmlDoc`，
**绕过了边缘缓存**（单文件分享走缓存、目录分享不走）→ 每次加载文档都读一次 R2。
新增 `serveShareDoc()` 统一走缓存，并把"必须是 html 且不太大"的校验收进去。
check.mjs 加了守卫防止回退。写测量脚本时自己也踩了两个坑，记一下：
`post()` 不取 JSON 的话拿到的是 Response、`.ok` 恒为 200 会把失败当成功；
缓存写入挂在 `waitUntil` 上是异步的，不等它落定就发第二次请求会测出"假未命中"。

**当前测试套件共 10 个**（Node 6 + 浏览器 4）：check ✅ / cost 18 ✅ / htmlshell 55 ✅ /
sharecache 36 ✅ / collect ✅ / backend 242 ✅ / collect_browser 42 ✅ / htmlshell_browser 31 ✅ /
linkclick 17 ✅ / pubbtn 19 ✅。README 加了「采集 / 分享的资源消耗（实测）」小节。pages.zip 已重建。
