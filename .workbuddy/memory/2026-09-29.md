## 第六轮：分享链接在界面上显示为「可读」形式

用户反馈：界面里生成的分享链接显示成 `.../s/<token>/%E8%8F%9C%E9%B8%9F.txt`，人眼读不出来；
希望**视觉上**看到的是 `.../s/<token>/菜鸟.txt`（跟浏览器地址栏一致），链接功能不变。

### 实现（纯前端展示层，服务端零改动）
- 新增 `prettySeg(name)`：先把文件名 `encodeURIComponent`，再用
  `replace(/(?:%[89A-F][0-9A-F])+/gi, ...decodeURIComponent...)` 把**连续的多字节 UTF-8 转义**还原成字符。
  效果 = 和浏览器地址栏一致：中文/日文/俄文/emoji 还原，而**空格 `%20`、`#` `%23`、`?` `%3F`、`%` `%25` 保持转义**
  （这几个不转义会把链接截断或改变语义）。
- 拆出 `shareUrlPretty(token, path, kind)`（可读，用于显示 + 复制 + 分享列表）
  和 `shareUrlRaw(token, path, kind)`（全 ASCII，用于**二维码**）。
- 二维码用 ASCII 版本的原因：`qrcodejs` 系列对多字节字符的 UTF-8 处理不可靠，
  全 ASCII 最稳；扫码结果仍是能正常打开的链接。
- 界面上额外给一个不显眼的「复制编码版」链接，需要粘进命令行/老客户端时用。
- 顺手修了一个隐患：`showShareResult` 原来只在 `%` 存在时无提示，现在把两种形式都明确给出。

### 验证
- 单元级：`prettySeg` / `shareNameSuffix` 抽出后跑 13 个文件名用例全过
  （菜鸟.txt、光速雷达.yaml、emoji😀.txt、日本語、ПРИВЕТ、my file.txt、a#b.txt、50%.txt、a?b.txt、a&b=c.txt …）。
- 浏览器级（CDP 真实渲染）：显示值 = `.../s/<token>/菜鸟.txt`、复制内容与显示一致、
  编码版兜底存在、二维码内容为 ASCII 版、分享列表同样可读、**用可读链接 fetch 能拿到正确正文**；
  另一个 `我的 文件 #1.txt` 用例确认中文还原而 `%20`/`%23` 保留。全部通过。

### 教训（已写进技能）
- 浏览器测试脚本里**不要用 bash heredoc 写含 `${...}` 和反引号的 JS**，shell 会吃掉；
  用 Write 工具直接落盘。
- 测试页面要先通过 `?path=<目录>` 让**应用自己**加载目标目录，不要在测试脚本里额外调 `load()` —— 
  会和启动时的 `load()` 抢，谁后返回谁生效，导致随机 404。

## 第七轮：左侧目录树重做（可读性 + 丝滑展开）

用户反馈：树的展开方式看不出"子项里还有没有内容"，只看得到当前文件夹的东西；
并且要求展开/折叠丝滑不卡顿。

### 后端
- 新增 `action=treeFull`：一次分页扫描整棵树（`buildFullTree()`），返回嵌套结构
  `{n,p,d,f,c,z,x}` —— n 名字 / p 路径 / d 子目录 / f 文件 / c 直接子项数 / z 递归体积 / x 被截断数。
  上限：扫描 12000 对象、单目录 500 文件，超了回传 `truncated`。
- 保留旧的 `action=tree`（移动弹窗还在用）。

### 前端（整块重写左上侧栏）
- `treeData / treeIdx / treeRefs / treeOpen` 四张表；`loadTree(force)` 带并发去重。
- 渲染：折叠节点 DOM 里只留一行；展开时才 `kidsHtml()` 建子节点，建完立刻 `registerRefs(inner)`。
- 动画：`.tkids` 用 `grid-template-rows:0fr → 1fr`，`.tkids-in{overflow:hidden;min-height:0}`。
  折叠/展开只改 class + caret 旋转 → 实测 400 项目录平均 1ms。
- 每个文件夹行右对齐显示**直接子项数量**徽标；空的显示灰色 0 且**不显示三角**（占位用 visibility:hidden 保持对齐）。
- 文件直接进树（子文件夹在前、文件在后，文件后面显示体积），**删掉了原来底部重复的"当前目录文件"列表**。
- 新增 `registerRefs() / refreshTreeSel() / markOpen() / revealInTree() / treeAll() / kidsOf()`。
- `load()` 改成 `Promise.all([list, loadTree])` + `markOpen()` + `revealInTree()`（进目录自动展开上级、滚到可见）。
- `openFile` 完成后只调 `refreshTreeSel()`，不再整树重建；`switchView` 也补了高亮刷新。
- 移动/批量移动弹窗的目录列举改用 `kidsOf()`（服务端实时查，缓存兜底），换掉已删除的 `ensureKids`。
- 只读分享页不再输出 `#batch` 那串批量操作 DOM（脚本里对 `getElementById('batch')` 判空）。

   教训：懒渲染的子节点必须当场登记引用；测试必须覆盖**两级**展开。
2. `treeIdx` 原来只索引文件夹，文件不在里面 —— 改成文件夹和文件统一入索引。
3. 只读页仍输出"批量删除"按钮 DOM（虽然不可达），已按 RO 屏蔽。

## 第十一轮：清理重复项 + 安全加固（防攻击 / 防刷流量）

### 清理
TEXT_EXT 160→159（`cnf` 重复）、TEXT_APP 22→20（`x-ndjson`、`x-yaml` 各重复一次）。
清理时别把有用的删掉：`x-yaml` 在前一组里还有一条，去掉末尾那条即可。

### 安全加固
1. **统一安全响应头出口**：`export default.fetch` 改成 `applySecurity(await handleRequest(...))`，
   所有响应（含 429/404/302）都带 `nosniff` / `Referrer-Policy` / `X-Frame-Options: DENY`，
   HTML 再加 `X-Robots-Tag: noindex`。改导出结构时括号会失衡，要用括号配平脚本核对。
2. **CSP + nonce**：appHtml 每次生成 16 字节随机 nonce，`<meta http-equiv="CSP">` +
   `<script nonce>`，允许 `self` 和二维码库的 jsdelivr。注意 `<script>` 现在带属性，
   提取内联脚本的测试正则要改成 `/<script[^>]*>/`。
3. **CSRF**：非 GET/HEAD 校验 `Origin` 与 `url.host` 一致，不一致 403。
   无 Origin 的客户端放行（不构成 CSRF）。放在 fetch 入口最前面，管理端与分享接口都覆盖。
4. **两层限速**（in-isolate Map，1 分钟窗口，`RATE_LIMIT`/`DOWNLOAD_LIMIT` 可配，0 关闭）：
   通用每 IP 每分钟 240 次（默认）；分享文件直连每 IP 每分钟 60 次——防刷流量专项，与通用额度独立。
   Map 超过 10000 个 key 会清理过期项，防内存膨胀。
5. **分享口令最短 6 位**（自定义口令太短返回 400），随机口令仍是 12 位 hex。
6. **恶意文件沙箱**：serveSharedFile 对 text/html / xhtml / svg+xml 加 `CSP: sandbox`。
   注意 HTML 本来就被 TEXTY 降级为 text/plain（那已经安全了），sandbox 主要挡 SVG。

### 测试（4 个文件全绿）
- `gen.mjs` 静态 **69 项**：三个变体的内联脚本 `new Function` 编译、id 引用、
  只读页零管理端元素、CSP/nonce/安全头来源、名单去重 159/20。
  ★ 内联脚本提取正则要改成 `/<script[^>]*>/`（script 现在带 nonce 属性）。
- `security.mjs` **46 项**：安全头、CSP（分享页+管理页、nonce 每次不同、脚本标签与 CSP 一致）、
  CSRF 三种写操作 403 / 同源放行 / 无 Origin 放行、RATE_LIMIT=0 关闭、口令强度、
  HTML 降级 text/plain、SVG sandbox、登录失败限速独立、名单去重。
- `ratelimit.mjs` **14 项**（RATE_LIMIT=6 / DOWNLOAD_LIMIT=3 的环境）：第 7 次 429、
  Retry-After、换 IP 不受影响、页面请求同额度、下载额度打光后目录页和 API 仍可用、429 也带安全头。
- `csp.mjs` 浏览器回归：管理页编辑/保存/上传/二维码（CDN 脚本在 CSP 白名单下能加载）、
  只读页查看器，全程零 CSP 违规。

### 顺手抓到的真 bug
**上传新文件后左侧目录树不刷新**：`handleFiles` 完成后只调 `load(state.path)`，
没调 `invalidateTree()`，新文件在树里看不见（直到下一次结构变更）。同样问题也在 `newText`。
两处都补了 `invalidateTree()`。

### 教训
- **bash heredoc 不可靠**（多次内容被 shell 吃掉导致没写入/语法错），写文件一律用 Edit/Write 工具。
- **残留的服务进程会占着端口并返回旧代码**：测试失败先确认没有旧进程在监听测试端口。

## 第十二轮：新增「上传文件夹」功能（评估 → 实施）

用户先问「应不应该加上传文件夹」，评估结论：**值得加、后端几乎不用动**，并指出三个必解坑
（限速误伤 / 手机端不可用 / 大目录误操作）。用户确认「现在就做」，于是实施。

### 后端改动（很小）
1. **限速豁免**：`handleRequest` 里算出 `isAdminWrite = pathname === adminPath + '/api' &&
   (PUT|POST|DELETE)`，命中时不走通用 `rateTake`。理由：上传文件夹天然会打几十上百个请求；
   这些操作受密码 + CSRF 保护，而真正公开的 `/s/*` 访客面仍照常限速（分两种测试锁死）。
2. **PUT 读取方式改成 `await request.arrayBuffer()`**（原来直接透传 `request.body` 流）。
   ★ 这是本轮最值钱的发现：Node/undici 里 `request.body` 流**读出来是空的**
   （`req.text()` 正常，但 `req.body.getReader()` 一个 chunk 都没有），
   所以本地 mock 环境里所有上传都写入了 0 字节，而生产 Workers 运行时不报错 ——
   **在 mock 上跑测试才暴露出来**。改成 arrayBuffer() 后两边都正确。

### 前端（appHtml 内，纯前端）
- 新增 `<input type="file" id="dirInput" webkitdirectory multiple hidden>` 与工具栏「上传文件夹」按钮。
- `collectFromInput(fileList)`：用 `file.webkitRelativePath` 得到相对路径（保留最外层文件夹名）。
- `scanDataTransfer(dt)` + `walkEntry(entry, prefix, out)`：拖拽时用 `webkitGetAsEntry` 递归遍历目录；
  **必须在 drop 回调里同步取 entry**（不能等到异步之后），再决定走文件夹流程还是普通多文件流程。
- `isJunkPath`：跳过 `.DS_Store` / `Thumbs.db` / `desktop.ini` / `__MACOSX/` / AppleDouble `._*`。
- `confirmTreeUpload(items)`：弹窗给出「N 个文件 / M 个文件夹 / 合计体积」+ 目标目录 + 覆盖提示。
- `uploadTree(items)`：先逐段 mkdir（含空文件夹占位），再 4 路并发传文件；
  进度面板显示「上传中 done/N（失败 x）」，条目按**相对路径**做 key（避免同名文件互相覆盖进度条）。
- `uploadOne(file, fullPath, progressKey)`：兼容旧调用（只传 file），失败时把 `status` / `retryAfter`
  挂在 Error 上，供退避逻辑判断。
- `backoffMs(status, retryAfter, attempt)`：429 时尊重 `Retry-After`（封顶 8s），其它错误指数退避。
- 触屏隐藏按钮：`@media (hover:none) and (pointer:coarse){ #btnUpDir{display:none} }`
  —— **必须放在顶层**，第一版被插进了 `@media(max-width:640px)` 块里形成嵌套 @media，整条规则失效。

### 抓到的三个真 bug
1. **模板字符串吃掉正则反斜杠**：`/(^|\/)\.DS_Store/` 写在 appHtml 的模板字符串里，
   `\/` 被解析成 `/`（未识别转义的 `\.` 也会丢反斜杠），结果内联脚本报
   `Invalid regular expression: /(^|/: Unterminated group`，**整页 JS 全废**。
   修法：在模板字符串里写 `\\/`、`\\.`。★ `node --check worker.js` 查不出，
   必须把内联脚本抽出来 `new Function(js)` 编译。
2. **嵌套 @media 无效**（同上，触屏按钮隐藏规则从未生效）。
3. 上传文件夹的 PUT 全写成空文件（上面第 2 条后端修复）。

- `folder.mjs` 浏览器端 **20 项**：按钮/输入框、垃圾识别 8 例、确认弹窗数量与体积、
  uploadTree 端到端（嵌套内容、空文件夹占位、进度 4/4、树刷新、停在原目录）、
  垃圾不进树、同名覆盖、backoffMs 7 个取值、触屏规则存在、进子目录后上传落到当前目录。
- `limcheck.mjs` **5 项**：同 IP 连发 12 个 PUT 全 200（豁免）；管理端 GET 第 6 次 429；
  访客 `/s/` 第 6 次 429；换 IP 不受影响。
- `gen.mjs` 静态 **22 项**；`regress.mjs` 主流程 **7 项**（编辑保存 / 单文件上传兼容 / 搜索 / 只读查看器）；
  `secrecheck.mjs` 安全 **12 项**（PUT 响应头、CSRF、CSP nonce、HTML→text/plain、SVG sandbox、访客 403）。

## 第十三轮：手机端复制修复 + 分享状态可见化

用户报两个问题：① 手机端点「复制」提示"复制失败，请手动选择"；② 打开分享弹窗时已有链接**延迟出现**，
且用户根本不知道哪些文件/文件夹已经分享过。

### ① 复制（根因：用户激活状态）
老实现只走 `navigator.clipboard.writeText`。它在异步回调（`post().then()`）里**必然失败** ——
Clipboard API 要求 transient user activation，手势早就过期了，于是只剩一句"请手动选择"，
而手机上根本没有可以选的东西。新实现三级降级：
1. `copyViaExec(v)`：同步 `execCommand('copy')` + 离屏 readonly textarea（`font-size:16px` 防缩放），
   **在点击手势里同步调用**，这是移动端 Safari 唯一可靠的路径。
2. 仍是 `navigator.clipboard.writeText`（桌面非手势场景可用）。
3. `manualCopy(v)`：弹窗把链接放进 readonly input 并**自动全选** + 「长按 → 拷贝」提示 +
   「再试一次」+ `navigator.share` 存在时的「系统分享」。
生成链接后的自动复制改成 `copyText(pretty, true)`（静默）：手势已过期，失败不再弹错误打扰用户。
旧的"复制失败，请手动选择"文案已彻底移除（静态断言锁死）。

### ② 分享可见性 + 无延迟（引入内存缓存）
新增 `shareCache = { list, byPath, loaded, at, loading }`：
- 启动时 `refreshShareCache(false)` 预载（管理页才发，只读页跳过，访客调 shares 接口是 403）。
- `mountShare` → `loadShareList` **先用缓存同步渲染**（链接与弹窗同一次 tick 出现），再后台确认。
  未加载完时显示「正在读取已有分享…」，绝不显示"还没有分享链接"（那会误导）。
- 数据结构拆开：`refreshSharePanels()` 只按缓存重渲染（**不发请求**），
  `reloadShares()` = 强制重取 + `applyShareUi()`。
  这样避免 applyShareUi → refreshSharePanels → refreshShareCache → applyShareUi 的无限循环。
- 可见性：`shBadge(path,isDir)`（列表行 + 编辑器标题的绿色「🔗 已分享」胶囊，点击直接开该条目的分享面板）、
  `shDot(path)`（目录树行的小图标）、工具栏 `分享管理 (N)`；
  新增 `openShareManager()` 面板按目标分组列出全部链接（类型标签 / 路径 / 有效期 / 复制 / 打开 / 取消）。
- 结构变化（删除、移动、改名、批量删除、取消分享、新建分享）后调 `reloadShares()`。

### 验证（4 个测试文件全绿）
- `share2.mjs` 浏览器 **28 项**：预载与标记、**弹窗同 tick 即有内容**（并断言中途没有"正在读取"）、
  分享管理分组、**真实 trusted 点击复制**（`Input.dispatchMouseEvent` 产生可信事件，toast=已复制到剪贴板）、
  新生成后计数与标记同步、取消+删除后收敛、只读页零标记且 shares 接口 403、手机 390 视口无溢出、
  强制两条复制路径都失败时的手动面板（断言选区 0..len 全覆盖）、`navigator.share` 按钮。
- `gen.mjs` 静态 20 项（三变体编译、分享函数齐备、复制走 execCommand、旧文案已移除、
  工具栏在 !RO 分支内、只读页不预载分享）。
- `regress.mjs` 主流程 11 项（列表/行内按钮、编辑保存、文件夹上传、搜索、批量条、只读查看器）。

### 教训
- **测"手势里才能成功"的 API 必须用可信事件**：`element.click()` 在 CDP 里不是 trusted；
  要用 `Input.dispatchMouseEvent` 发 mousePressed/mouseReleased。
- 静态文本匹配判断"某按钮是否存在于某页面"会反复误报（字符串在共享 JS 里）；
  这类判断只能在浏览器里数真实 DOM。本轮又踩了两次。

## 第十四轮：删除残留空壳文件夹 + 同名文件处理策略 + 目录图标分层配色

用户报三件事：① 删掉上传的文件夹后，界面里还留着一个空的同名文件夹（只删了里面的文件）；
② 问同名文件要不要做重复判断（他自己指出"同名 ≠ 内容相同"）；③ 希望不同层级的文件夹图标颜色不同。

### ① 空壳文件夹（真 bug）
复现结论：本地 mock 里删除是**正确**的（`collectKeys(prefix)` 会把占位键 `d/x/` 一起列出并删掉）。
所以根因是**代码假设了"list 一定会返回与 prefix 完全相同的那个键"** —— 这个假设不成立时，
递归删除只会删掉子文件，目录占位键留下，于是看起来就是"文件夹还在、里面空了"。
修法（两处都不再依赖该假设）：
- 新增 `collectDirAll(bucket, dirPrefix)`：`collectKeys` 之后再逐个 `head()` 补上
  `dirPrefix` 与无斜杠的 `bare` 两种形态，确保占位键一定在删除集合里。
- `deletePath(dir)`：删完**再 head 校验一次**，还活着就补一刀（并计入返回数）。
- `moveObjects`：源是目录时（`srcPrefix` 以 `/` 结尾）同样用 `collectDirAll`，
  搬完再清理源位置的占位键 —— 否则改名/移动也会留下空壳。
- `moveObjects` 顺带搬运 `customMetadata.mtime`，不然移动后"完全一致"的判断会退化成只看大小。

### ② 同名文件处理（不动内容，按大小+时间判断）
- 新接口 `action=manifest&path=`：返回该目录（含子目录）下所有文件的 `{p 相对路径, s 大小, m 原始修改时间, t 上传时间}`，
  分页扫描上限 20000 条，`truncated` 标记；访客受 `scanBase` 分享范围限制。
- PUT 新增读取 `X-File-Mtime` 头 → `customMetadata: { mtime }`；前端 `uploadOne` 自动带上 `file.lastModified`。
  这样后续上传的文件都有原始时间，判断才准。
- 前端：`fetchManifest` → `classifyUpload` 分三类（`same` 大小+时间都一致 / `differs` 同名但可能不同 / `fresh` 无同名）
  → 弹窗给统计（带绿/黄圆点）+ 三个单选（**跳过**（默认）/ **覆盖** / **都保留**）+ 一个复选框
  「连完全一致的文件也重新上传」。
- `uploadTree(items, policy, entries)`：先算"真正要传的清单"（跳过的跳过、都保留的用
  `freeUploadName()` 生成 `名字 (1).txt` 并去重），进度与 toast 都反映「跳过 N 个同名文件」。
- 语义细节：`skip` 模式下同名一律不传；`overwrite`/`keepboth` 模式下「完全一致」的默认跳过（省流量），
  勾选复选框才强制重传。默认策略（程序化调用、老测试）保持 `{mode:'overwrite', reuploadSame:true}` = 老行为。

### ③ 目录图标分层配色
`DIR_COLORS = [琥珀, 蓝, 紫, 绿, 橙]`，`dirIcon(path, open)` 按
`path ? depthOf(path)+1 : 0` 取色 —— **根目录单独占 0 号色位**，否则根与它的一级子目录会撞色
（第一版就是这样，访客页上"根 + 一级"都是琥珀）。树、列表、移动弹窗的目录列举共用该函数。

### 验证（3 个测试文件全绿）
- `del2.mjs` 后端 **23 项**：正常环境 + **`strictPrefix` 模拟"list 不返回占位键"的环境**，
  两种情况都断言删除后 R2 一个对象不剩、树里彻底消失；目录改名后源位置不留空壳、嵌套文件正常搬走；
  manifest 的字段与 mtime 记录；manifest 不越界。
- `dup.mjs` 浏览器 **23 项**：分层配色（根/一级/二级互不相同、列表与树一致）、
  比对统计（1 个一致 + 1 个可能不同）、三种策略的实际效果（跳过不动云端 / 覆盖替换 / 都保留生成 `(1)`）、
  勾选强制重传时跳过数归零、无同名时不显示策略选项。
- `regress2.mjs` 端到端 **14 项**：**完整复现用户场景** —— 界面上传一个含嵌套与空目录的文件夹，
  再从列表点「删除」→ 列表、树、服务端全部清空，零残留；外加编辑保存、搜索、批量条、
  访客页配色与零写入口。

### 教训
- **别假设对象存储的 list 会返回"与 prefix 完全相同"的键**：删除/搬移目录必须显式处理占位键，
  并在删后做一次校验。测试要专门模拟"list 不返回它"的环境（mock 加 `strictPrefix` 开关）。
- 前端测试里目录条目要用**相对当前目录**的路径（页面停在 `订阅` 里时写 `订阅/x.txt` 会落到 `订阅/订阅/`，
  于是"没有同名冲突"，测试看起来像功能坏了）。
- 分享口令有最短 6 位限制，测试里用 `ro1` 建分享会 400 —— 会连累后面所有依赖分享页的断言。

## 第十五轮：自动换行（默认开启 + 开关 + Alt+Z + 偏好持久化）

用户截图：打开 `fluyun_subscription.txt`（一整行 8460 字符的订阅链接），编辑器只有横向滚动、
看不到全貌。原实现是 `<textarea wrap="off">`，即**从一开始就没开自动换行**。

### 设计（对齐大众习惯）
- **默认开启换行**：打开文本文件的目的基本是读；订阅链接/base64 这类超长单行必须能看全。
- 工具栏加一个**状态按钮**「自动换行」（放在 A-/A+ 右边），开启时高亮成蓝色并 `aria-pressed=true`
  —— 和 VS Code 的状态开关一个路子，而不是塞个 checkbox。
- **快捷键 `Alt+Z`**（VS Code / 许多编辑器通用），按钮 tooltip 里写明；键盘事件同时覆盖管理端与只读页。
- **偏好持久化**：`localStorage.cfwtxt_wrap`（`'0'` = 关闭），与字号 `cfwtxt_font` 一致；
  首次访问默认开启。
- **只读查看器同样支持**（访客也会遇到超长行），共用同一份偏好。
- CSS：开启 `white-space:pre-wrap; overflow-wrap:anywhere`（关键：长串无空格，只有 `anywhere`
  才能真正断开）；关闭 `white-space:pre; overflow-x:auto`。textarea 同时设 `wrap` 属性。

### 踩坑
- **类名撞车**：第一版给 textarea 加 `class="wrap"`，而 `.wrap` 是**布局容器类**
  （`flex:1;display:flex;padding:14px 18px 60px`），会串进 textarea 的 padding/flex。
  改用独立类名 `wrapon` / `wrapoff`。改任何类名前先 grep 一下是否已被占用。
- 页面刷新后编辑器是空的（不会自动重新打开文件），测试里要显式 `openFile()` ——
  否则断言 "保存内容与编辑器一致" 会因为编辑器为空而假失败。
- 访客分享页的相对路径**已含分享目录**，不能重复拼（`fniao/x.txt` 在 scope=fniao 的页面里会 404）。

### 验证（`wrap.mjs` 浏览器端 22 项全过）
默认开启（`wrap=soft` / `scrollWidth === clientWidth`，8460 字符不溢出）、
关闭后出现横向滚动（60484 > 886）且内容不变、**刷新后偏好保持**、
**Alt+Z 用 CDP 真实按键事件**切换并提示、按钮 tooltip 含快捷键、
切换前后**保存内容与云端逐字一致**、访客页同款开关且沿用偏好、
多行文本不受影响、样式未被布局类污染（`padding-left` 仍是 16px）、
手机 390 视口按钮可见且在视口内。
